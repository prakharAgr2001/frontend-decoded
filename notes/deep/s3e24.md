## Key points
- **Throttle** = run **at most once per interval**, steadily, **while** the events keep coming.
- Use it for scroll progress bars, drag handlers, and continuous position updates.
- Debounce waits for silence; throttle keeps a steady rhythm. For visuals, `requestAnimationFrame` is often even better.

## Interview answer
> Throttling limits a function to at most once per time window while events keep firing, which suits continuous interactions like scrolling or dragging where you want regular updates rather than a single update at the end. A naive throttle drops the final event, so I add a trailing call to capture the last state. For anything visual I prefer requestAnimationFrame, which naturally runs once per frame, and for visibility checks I use IntersectionObserver instead of scroll listeners.

## The analogy
A metro that leaves every 3 minutes no matter how many people rush in. Debounce would be a metro that only leaves once nobody has entered for 3 minutes.

## How it works
```compare
Debounce || Throttle
Runs once, after the burst ends || Runs regularly during the burst
Search box, autosave || Scroll progress, drag, resize preview
300 events → 1 call || 300 events over 3 s with 100 ms → ~30 calls
```

```js
function throttle(fn, interval = 100) {
  let last = 0, timer;
  return (...args) => {
    const now = Date.now(), remaining = interval - (now - last);
    clearTimeout(timer);
    if (remaining <= 0) { last = now; fn(...args); }
    else timer = setTimeout(() => { last = Date.now(); fn(...args); }, remaining);   // trailing call
  };
}

window.addEventListener('scroll', throttle(updateProgressBar, 100), { passive: true });
```

## Common traps
- **Naive throttle drops the last event**, so the final scroll position is never shown. Add a trailing call.
- **Throttling with timers for animation.** Use `requestAnimationFrame` so updates align with frames.
- **Scroll listeners to detect visibility.** `IntersectionObserver` does it without running code on every scroll.

## See it yourself
Log inside a scroll handler with and without throttle and scroll quickly: hundreds of logs vs a steady handful.

## Quick quiz
<details><summary>Which would you use for a scroll progress bar, debounce or throttle?</summary>

Throttle (or requestAnimationFrame), because it needs regular updates while scrolling.
</details>
<details><summary>What's the "trailing call" in throttle?</summary>

One final call after the last event, so the last state isn't lost when it fell inside the wait window.
</details>
<details><summary>What's better than throttling scroll to detect when an element appears?</summary>

IntersectionObserver.
</details>
