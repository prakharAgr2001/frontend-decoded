## Key points
- **Streaming SSR** sends the page in pieces: first the **shell with loading placeholders**, then each slow section as soon as its data is ready.
- It works because HTTP responses can arrive in chunks; the browser renders as it goes.
- A tiny inline script swaps each streamed section into its placeholder.

## Interview answer
> With streaming SSR the server doesn't wait for all data before responding. It flushes the HTML shell and Suspense fallbacks immediately, so the user sees layout and fast content early, then streams each boundary's HTML as its data resolves, along with a small script that moves it into place. In React this is renderToPipeableStream or the streaming APIs in frameworks like Next.js. The important caveat is that once the first bytes are sent, the status code and headers are fixed.

## The analogy
A thali served one bowl at a time. Rice and dal arrive first so you can start eating; the dish that takes longest to cook is brought out when it's ready, into the empty space already on your plate.

## How it works
```steps
Request | server starts rendering
Flush the shell | header, layout, fallbacks sent immediately
Slow data resolves | e.g. reviews from a slow API
Stream that HTML | plus a small script that swaps it in
Close the response | when every boundary is done
```

```jsx
// Node + React: send the shell as soon as it's ready
const { pipe } = renderToPipeableStream(<App />, {
  onShellReady() {
    res.setHeader('Content-Type', 'text/html');
    pipe(res);
  },
});
```

## Common traps
- **Status codes are locked once streaming starts.** You can't send a 404 or redirect after the shell is out, so decide those before the shell.
- **Buffering proxies** (some CDNs, compression settings) can hold the whole response and kill streaming.
- **Fallback layout shift.** Size your fallbacks like the final content to avoid CLS.

## See it yourself
DevTools → Network → the document → **Timing**: a long "Content Download" phase means it was streamed. View Source shows hidden `<div hidden id="S:0">` chunks and small `$RC(...)` scripts at the bottom.

## Quick quiz
<details><summary>What gets sent first in streaming SSR?</summary>

The shell: layout, fast content and Suspense fallbacks.
</details>
<details><summary>Why can't you return a 404 halfway through a streamed page?</summary>

Status and headers are sent with the first chunk; after that they can't be changed.
</details>
<details><summary>What makes streaming possible at the HTTP level?</summary>

Response bodies can arrive in pieces (chunked transfer in HTTP/1.1, DATA frames in HTTP/2 and 3), and browsers parse HTML incrementally.
</details>
