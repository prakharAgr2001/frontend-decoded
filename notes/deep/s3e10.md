## Key points
- **Plain `<script>`**: stop parsing, download, run, then continue.
- **`async`**: download in parallel, **run as soon as it arrives**, in any order.
- **`defer`**: download in parallel, **run after parsing finishes, in document order**, before `DOMContentLoaded`. `type="module"` scripts are deferred by default.

## Interview answer
> A classic script blocks HTML parsing while it downloads and executes. async downloads in parallel and executes as soon as it's ready, which can be before or after parsing and in any order, so it suits independent scripts like analytics. defer also downloads in parallel but waits until the document is parsed and runs scripts in order, so it's the right default for application code that depends on the DOM or on other scripts. Module scripts behave like defer by default.

## The analogy
Guests arriving at a wedding. **Plain:** the ceremony stops every time a guest walks in. **async:** guests walk in whenever they arrive and start dancing immediately, in random order. **defer:** guests wait outside and walk in together, in the order on the list, after the ceremony.

## How it works
```compare
Attribute || Behaviour
none || Blocks parsing while downloading and running
async || Parallel download, runs on arrival, no order guarantee
defer || Parallel download, runs after parsing, in order
type="module" || Deferred by default (add async to change)
```

```html
<script src="/vendor.js" defer></script>
<script src="/app.js" defer></script>            <!-- runs after vendor.js -->
<script src="https://analytics.example.com/a.js" async></script>
```

## Common traps
- **Dependent scripts with `async`** break randomly, because the order changes with network timing.
- **`defer` does nothing on inline scripts.** It only applies to scripts with `src`.
- **`async` doesn't make the script cheap.** It still runs on the main thread when it arrives.

## See it yourself
DevTools → **Performance** → record a load: plain scripts appear as gaps in HTML parsing; deferred scripts run as a group after parsing.

## Quick quiz
<details><summary>Which attribute keeps execution order?</summary>

`defer` (and module scripts by default). `async` does not.
</details>
<details><summary>Where would you use async?</summary>

For independent third-party scripts like analytics that don't depend on other scripts or on the DOM being complete.
</details>
<details><summary>When do deferred scripts run relative to DOMContentLoaded?</summary>

After parsing completes and before the DOMContentLoaded event fires.
</details>
