## Key points
- **Incremental Static Regeneration (ISR)** = a static page with an **expiry time**.
- After it expires, the next visitor **still gets the old page instantly**, while that one page is rebuilt in the background.
- Everyone after that gets the fresh version. It's static speed with data that stays reasonably current.

## Interview answer
> ISR serves pre-rendered static pages from a cache, but each page has a revalidation window. When a request comes in after the window has passed, the cached page is still served immediately, and a background regeneration is triggered for that page only. Once it succeeds, the cache is updated for subsequent visitors. It's the stale-while-revalidate idea applied to pages, and frameworks also support on-demand revalidation when you know data has changed.

## The analogy
A café's daily specials board. The board is rewritten only when it's out of date, and only after the first customer of the day notices. That customer still reads yesterday's board, but the staff update it right away for everyone after.

## How it works
```steps
Page built | served as static HTML from cache
Revalidate window passes | e.g. 60 seconds
Next visitor | still gets the OLD page, instantly
Background rebuild | of just that page
Visitors after that | get the NEW page
```

```jsx
// Next.js: rebuild this page at most once a minute
export const revalidate = 60;

// Or on demand, e.g. after an admin edits a product
import { revalidatePath } from 'next/cache';
revalidatePath('/product/42');
```

```http
# Same idea at the HTTP/CDN level
Cache-Control: s-maxage=60, stale-while-revalidate=300
```

## Common traps
- **The first visitor after expiry sees stale data.** It's "eventually fresh", not real-time. Don't use it for stock counts at checkout.
- **Pages nobody visits stay stale** because regeneration is triggered by a request.
- **Choosing the window.** Too short = lots of rebuilds; too long = stale content. Prefer on-demand revalidation when you can.

## See it yourself
Deploy a Next.js page with `revalidate = 10` that prints the time. Refresh after 10 s: you see the old time once, then the new time on the next refresh.

## Quick quiz
<details><summary>After the revalidate time passes, what does the next visitor see?</summary>

The old cached page, immediately. A rebuild starts in the background for later visitors.
</details>
<details><summary>What's the HTTP equivalent of ISR?</summary>

`Cache-Control: s-maxage=…, stale-while-revalidate=…` on a CDN.
</details>
<details><summary>How can you update a page right after data changes instead of waiting?</summary>

On-demand revalidation, e.g. `revalidatePath()` or `revalidateTag()` called from a webhook or admin action.
</details>
