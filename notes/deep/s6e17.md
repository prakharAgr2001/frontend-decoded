## Key points
- **OT (Operational Transformation)**: a **central server orders operations** and transforms late ones against earlier ones. Lean documents, but it needs a server.
- **CRDT (Conflict-free Replicated Data Type)**: every character gets a **permanent unique id**; edits reference ids, so they **merge in any order**, even peer-to-peer and offline. Costs extra metadata and tombstones.
- **Don't write your own.** Use **Yjs** or **Automerge**, and spend your time on presence, cursors and undo.

## Interview answer
> Operational Transformation sends position-based operations through a central server, which establishes an order and transforms concurrent operations so every client converges; Google Docs popularised it. CRDTs give each element a unique, permanent identity and define merges that are commutative, so replicas converge regardless of order, enabling offline and peer-to-peer collaboration, at the cost of extra metadata and deleted-element tombstones. Both are subtle to implement correctly, so in practice I'd use a proven library like Yjs or Automerge and focus on the product features around it.

## The analogy
**OT** is a referee who receives everyone's moves and announces the official order, adjusting moves that came in late. **CRDT** is a game where every piece has a unique serial number, so players can move independently and their boards always end up identical when they compare.

## How it works
```compare
OT || CRDT
Central server orders all operations || No central authority required
Operations use positions, transformed on conflict || Operations reference unique element ids
Small document size || Extra metadata and tombstones
Hard offline / peer-to-peer || Built for offline and peer-to-peer
Google Docs || Yjs, Automerge (Figma-style multiplayer, local-first apps)
```

## Common traps
- **Writing your own OT or CRDT.** Edge cases are endless; use a battle-tested library.
- **Ignoring metadata growth** in long-lived CRDT documents; use libraries with compaction.
- **Forgetting the product parts**: presence, cursors and per-user undo matter as much as merging.

## See it yourself
In Google Docs, turn on offline mode, make edits while disconnected, then reconnect: your edits merge with others' changes.

## Quick quiz
<details><summary>Key difference between OT and CRDT?</summary>

OT relies on a central server to order and transform position-based operations; CRDTs use unique element ids so edits merge in any order without central coordination.
</details>
<details><summary>Which suits an offline-first notes app with no server?</summary>

A CRDT (e.g. Yjs or Automerge).
</details>
<details><summary>What do CRDTs cost?</summary>

Extra metadata per element and tombstones for deleted items, so documents grow larger.
</details>
