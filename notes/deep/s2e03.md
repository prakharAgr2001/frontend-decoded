## Key points
- **Client-side routing:** JavaScript intercepts link clicks, changes the URL with `history.pushState()`, fetches data and swaps only part of the page. No full page reload.
- The **Back button** fires a `popstate` event, which the router handles.
- Refreshing a deep URL (`/products/42`) can **404** if the server isn't told to serve `index.html` for every route.

## Interview answer
> A client-side router listens for link clicks, prevents the browser's default navigation, and updates the URL using the History API's pushState. It then renders the matching component and fetches only the data it needs, so the page doesn't reload. Back and forward trigger popstate, which the router uses to render the previous route. Because the server only knows index.html, it must be configured to return index.html for all app routes, otherwise a refresh on a nested URL returns 404.

## The analogy
A mall map screen. Tapping a shop doesn't send you to a new building; the same screen just redraws the map for that shop. But if someone gives a visitor the address "Shop 42" directly, the security guard (the server) must know to send them to the map screen, not say "no such building".

## How it works
```steps
Click a <Link> | the router calls event.preventDefault()
Update the URL | history.pushState({}, '', '/products/42')
Render the route | match the URL to a component
Fetch only data | JSON from the API, not a new HTML page
Back button | popstate event → render the previous route
```

```js
// The core of every router, in a few lines
document.addEventListener('click', e => {
  const a = e.target.closest('a[data-link]');
  if (!a) return;
  e.preventDefault();
  history.pushState({}, '', a.href);
  render(location.pathname);
});
window.addEventListener('popstate', () => render(location.pathname));
```

```nginx
# Server: send index.html for any route the files don't match
location / { try_files $uri /index.html; }
```

## Common traps
- **The refresh 404.** Fix it with a rewrite rule (Nginx `try_files`, Netlify `/* /index.html 200`).
- **Scroll position and focus.** A router must restore scroll on Back and move focus for screen-reader users.
- **Hash routing (`/#/page`)** avoids the server issue but looks dated and is worse for SEO.

## See it yourself
Open YouTube → DevTools → **Network** → filter **Doc**. Click a video: no new document loads; filter **Fetch/XHR** and you'll see JSON requests instead.

## Quick quiz
<details><summary>Which browser API lets you change the URL without reloading?</summary>

The History API: `history.pushState()` (and `replaceState()`).
</details>
<details><summary>Why does refreshing /products/42 give a 404 on some SPAs?</summary>

The server looks for a real file at that path and doesn't find one. It must be configured to serve index.html for all app routes.
</details>
<details><summary>What event fires when the user presses Back?</summary>

`popstate`.
</details>
