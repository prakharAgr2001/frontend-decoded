## Key points
- Classic hydration is **all or nothing**: the whole page hydrates in one go before anything works.
- With React 18+, each **`<Suspense>` boundary hydrates on its own**, and React yields to the browser between chunks.
- If you click a part that isn't hydrated yet, React **hydrates that part first, then replays your click**.

## Interview answer
> React 18 introduced selective hydration. When the page is wrapped in Suspense boundaries, React can hydrate each boundary independently instead of the whole tree at once, and it yields between them so the browser can handle input. If the user interacts with a boundary that hasn't hydrated, React prioritises it and replays the event afterwards. It improves responsiveness, but it doesn't reduce the total JavaScript that's downloaded and executed.

## The analogy
Opening a big store floor by floor instead of keeping the whole building shut until every floor is ready. If a customer walks up to the third floor first, staff rush to open that floor next.

## How it works
```steps
Server HTML for all sections | page fully visible
Hydrate boundary by boundary | React yields between them
User taps a not-yet-ready section | React bumps it to the front
Hydrate it, replay the click | the tap isn't lost
```

```jsx
<Layout>
  <Header />
  <Suspense fallback={<Spinner />}>
    <Comments />          {/* hydrates independently */}
  </Suspense>
  <Suspense fallback={<Spinner />}>
    <Recommendations />   {/* hydrates independently */}
  </Suspense>
</Layout>
```

## Common traps
- **It doesn't make the JS smaller.** The same code still downloads and runs; only the order and chunking change.
- **No boundaries = no benefit.** Without Suspense boundaries, the tree still hydrates as one unit.
- **Too many tiny boundaries** add overhead and can cause flickering fallbacks.

## See it yourself
In a React 18 SSR app with Suspense around heavy sections, record **Performance** with CPU throttling: hydration appears as several smaller tasks instead of one long one.

## Quick quiz
<details><summary>What unit does React hydrate independently?</summary>

Each Suspense boundary.
</details>
<details><summary>What happens if a user clicks an un-hydrated boundary?</summary>

React hydrates that boundary with priority, then replays the click event.
</details>
<details><summary>Does selective hydration reduce bundle size?</summary>

No. It changes when and in what order hydration work happens, not how much code is shipped.
</details>
