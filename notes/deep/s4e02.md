## Key points
- There are **five kinds of state**, and each has a natural home:
- **Local UI** (open, active tab) → `useState`. **Shared client** (cart, theme, user) → context or a store. **Server** (products, orders) → a server cache like React Query. **URL** (search, filters, page) → the address bar. **Form** (values, errors) → a form library.
- Most state bugs come from putting state in the **wrong home**.

## Interview answer
> I classify state before choosing a tool. Local UI state stays in useState. Client state shared across distant components goes in context or a lightweight store. Data that comes from the server is server state and belongs in a server-cache library like React Query, which handles caching, refetching and staleness. Anything that should survive a refresh or be shareable goes in the URL. Complex form state goes in a form library. A common mistake is copying server data into a global store and hand-writing loading flags and refetch logic.

## The analogy
Organising a kitchen: spices near the stove (local), the fridge for shared ingredients (shared client), the market for fresh produce you can't store forever (server), the recipe card you can hand to a friend (URL), and the order pad for what a customer is writing down (form).

## How it works
```steps
Does it come from the server? | → server cache (React Query, SWR, RTK Query)
Should it survive refresh or be shareable? | → URL (path or query string)
Do distant components need it? | → context or a store
Is it a form? | → form library
Otherwise | → local useState
```

```compare
State || Home
isOpen, activeTab, hovered || useState
cart, theme, logged-in user || context or store (Zustand, Redux)
products, orders, prices || React Query / SWR / RTK Query
?q=shoes&sort=price&page=2 || URL search params
values, touched, errors || React Hook Form or similar
```

## Common traps
- **Server data in Redux/Context** means rewriting caching, loading flags and refetching by hand.
- **Filters in useState** are lost on refresh and can't be shared. Put them in the URL.
- **Everything global** makes every update re-render too much and couples unrelated features.

## See it yourself
Open any shopping site, apply filters, then refresh or copy the URL to another tab. If the filters survive, they're in the URL.

## Quick quiz
<details><summary>Where should a list of products fetched from an API live?</summary>

In a server-state cache (React Query, SWR, RTK Query), not copied into a global client store.
</details>
<details><summary>What state belongs in the URL?</summary>

Anything that should survive a refresh, be shareable/bookmarkable or work with Back: search, filters, sort, pagination, selected tab.
</details>
<details><summary>What three questions decide where state goes?</summary>

Does it come from the server? Should it survive refresh or be shared? Do distant components need it?
</details>
