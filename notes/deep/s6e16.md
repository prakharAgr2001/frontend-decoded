## Key points
- If two people edit and the app saves **whole documents**, the **last save wins** and someone's words disappear.
- Instead, send **operations** (`insert 'h' at 1`). But positions shift when edits happen at the same time, so operations must be **adjusted**.
- For forms, use **optimistic concurrency**: `PUT` with `If-Match: <etag>` → **`412 Precondition Failed`** means someone else changed it first.

## Interview answer
> Saving the whole document causes lost updates when two people edit concurrently, because the last write overwrites the other. Collaborative editors send fine-grained operations instead, but concurrent operations refer to positions that may have shifted, so they need to be transformed or modelled so they converge. For ordinary forms and records I use optimistic concurrency control with ETags: the client sends If-Match with the version it loaded, and if the server's version changed it returns 412, so the client can merge or ask the user. Pessimistic locking works but frustrates users, so I reserve it for things like tickets, not live text.

## The analogy
Two people editing the same printed page and both photocopying their version back into the folder. Whoever copies last wins, and the other person's corrections vanish.

## How it works
```steps
Start | text = "cat"
Riya | insert "h" at position 1 → "chat"
Arjun, at the same time | delete position 2 (the "t" in "cat")
Applied blindly on "chat" | deletes "a" → "cht" (wrong)
Adjusted for Riya's insert | delete position 3 → "cha" (both intents kept)
```

```js
// Forms: optimistic concurrency with ETags
const res = await fetch('/api/profile', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json', 'If-Match': etag },   // version we loaded
  body: JSON.stringify(profile),
});
if (res.status === 412) showConflictDialog();                          // someone saved first
```

## Common traps
- **Last-write-wins on shared documents** silently loses work.
- **Locking live text**: a forgotten open tab blocks everyone.
- **Ignoring 412**: overwriting anyway defeats the protection.

## See it yourself
Open the same Google Doc in two windows (or with a friend) and type in the same sentence: coloured, named cursors and both edits survive.

## Quick quiz
<details><summary>Why does "save the whole document" lose edits?</summary>

The last save overwrites the entire document, including changes made by others since it was loaded.
</details>
<details><summary>"cat": Riya inserts "h" at 1, Arjun concurrently deletes at 2. What's the right result?</summary>

"cha": Arjun's delete must be shifted to position 3 because of Riya's insert.
</details>
<details><summary>What does a 412 response mean with If-Match?</summary>

The resource changed since your version (ETag mismatch), so your update was rejected to avoid overwriting someone else's change.
</details>
