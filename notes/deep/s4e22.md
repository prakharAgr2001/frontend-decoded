## Key points
- Revision episode: interview questions on **URL state, forms, state machines and Immer**.
- Know what belongs in the URL, controlled vs uncontrolled inputs (and the focus-loss bug), replacing boolean flags with a status machine, and how Immer mutates safely.

## Interview answer
> Shareable and navigable state goes in the URL, form state is handled with uncontrolled inputs and a form library where possible, async flows use a single status with explicit transitions instead of several booleans, and Immer lets me write readable updates while keeping state immutable.

## Quick quiz
<details><summary>What belongs in the URL, and what doesn't?</summary>

In: search, filters, sort, page, selected tab, opened item ID. Out: secrets/tokens/personal data, huge objects, temporary UI like hover or open dropdowns.
</details>
<details><summary>Controlled vs uncontrolled, and why might an input lose focus on every keystroke?</summary>

Controlled: React state holds the value; uncontrolled: the DOM does. Focus loss happens when the input's component is defined inside another component (new type every render) or has an unstable key, so it remounts.
</details>
<details><summary>Your component has isLoading and isError both true. How do you fix the design?</summary>

Replace the booleans with one status ('idle' | 'loading' | 'success' | 'error') and explicit transitions, so impossible combinations can't exist.
</details>
<details><summary>How does Immer let you "mutate" state safely?</summary>

It gives you a Proxy draft, records your changes, copies only the changed paths, shares the rest, and returns a new frozen object.
</details>
