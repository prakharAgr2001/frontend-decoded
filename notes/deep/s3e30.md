## Key points
- To stop one long task from freezing the page, **break it into chunks** and **yield** to the browser between them.
- Slice by **time** (~10 ms), not by a fixed item count.
- **`await scheduler.yield()`** continues near the front of the queue; `setTimeout` goes to the back. `await Promise.resolve()` **does not yield at all** (it's a microtask).

## Interview answer
> I break long work into time-sliced chunks of roughly 5 to 10 milliseconds and yield back to the browser between them, so input and rendering can happen. scheduler.yield is the best option where supported, because the continuation is prioritised ahead of other queued tasks, while setTimeout puts it at the back of the queue. scheduler.postTask lets me set priorities like user-blocking or background. Awaiting a resolved promise doesn't yield, since microtasks run before the browser renders.

## The analogy
Mopping a long corridor while people need to walk through. Mop a few metres, step aside to let people pass, then continue, instead of blocking the whole corridor until it's done.

## How it works
```js
async function processAll(items) {
  let deadline = performance.now() + 10;
  for (const item of items) {
    process(item);
    if (performance.now() > deadline) {
      await yieldToMain();                      // let input + paint happen
      deadline = performance.now() + 10;
    }
  }
}

function yieldToMain() {
  if (globalThis.scheduler?.yield) return scheduler.yield();
  return new Promise(resolve => setTimeout(resolve, 0));
}

// Priorities
scheduler.postTask(() => sendAnalytics(), { priority: 'background' });
```

## Common traps
- **Microtasks don't yield.** The browser only renders and handles input between tasks.
- **Fixed item counts.** 100 items may take 2 ms on a laptop and 60 ms on a cheap phone; slice by time.
- **Yielding inside a loop that mutates shared state** can leave UI half-updated; design chunks to be safe.

## See it yourself
DevTools → **Performance**: one big task with a red corner before; many small tasks with gaps after chunking.

## Quick quiz
<details><summary>Why doesn't await Promise.resolve() help a long task?</summary>

It schedules a microtask, which runs before the browser can render or process input, so the main thread never gets a break.
</details>
<details><summary>Advantage of scheduler.yield over setTimeout?</summary>

The continuation goes near the front of the queue, so your work resumes promptly instead of waiting behind other tasks.
</details>
<details><summary>Why slice by time instead of by item count?</summary>

Device speed varies a lot; a time budget keeps chunks short on slow phones too.
</details>
