## Key points
- **Presence** (online / offline / last seen) comes from **connections + heartbeats + a TTL**: `SET presence:riya online EX 60`, renewed on every heartbeat.
- Count **connections, not users**: laptop closed but phone open = still online. **Debounce offline** to avoid flapping.
- Send presence updates only to people **currently viewing**, and throttle "typing…" to about one event every 3 seconds.

## Interview answer
> Presence is derived from active connections. Each heartbeat refreshes a short-lived key with a TTL in an in-memory store like Redis, so if a device disappears without closing its connection, the key simply expires. A user is online if any of their connections is alive, and I debounce the transition to offline to avoid flickering during brief reconnects. To keep fan-out manageable, presence and typing indicators are sent only to users who are currently viewing the relevant chat, typing events are throttled and expire automatically, and none of this goes into the main database.

## The analogy
An office attendance board where your name stays lit only while your badge keeps checking in every minute. If you leave without swiping out, the light goes off on its own when the check-ins stop.

## How it works
```steps
Socket connects | INCR connections:riya, SET presence:riya online EX 60
Each heartbeat | refresh the TTL
Last connection closes | wait a few seconds (debounce) before marking offline
No heartbeat at all | TTL expires → offline automatically
Fan-out | only to users viewing that chat or contact list
```

```js
// On each heartbeat for a user
await redis.set(`presence:${userId}`, 'online', { EX: 60 });

// Typing indicator: throttle on the client, auto-expire on the receiver
const sendTyping = throttle(() => ws.send(JSON.stringify({ type: 'typing', chat })), 3000);
input.addEventListener('input', sendTyping);
```

## Common traps
- **Storing presence in the main database**: constant writes for data that's useless a minute later. Use an in-memory store with TTLs.
- **Offline flapping** on every brief disconnect. Debounce it.
- **Broadcasting presence to every contact** of every user = enormous fan-out. Send only to active viewers.

## See it yourself
On WhatsApp, watch a friend's status switch between "online" and "last seen…" and notice the small delay before it changes after they leave.

## Quick quiz
<details><summary>How does a TTL handle a device that disappears without disconnecting?</summary>

Heartbeats stop refreshing the key, so it expires and the user becomes offline automatically.
</details>
<details><summary>Why count connections instead of users?</summary>

A user with several devices is online as long as any one of them is connected.
</details>
<details><summary>How do you keep "typing…" cheap for a 200-person group?</summary>

Throttle typing events (~1 per 3 s), send only to people viewing the chat, auto-expire the indicator, and never store it in the database.
</details>
