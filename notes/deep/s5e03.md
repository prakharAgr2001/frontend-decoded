## Key points
- **REST**: best for many different clients, public APIs and simple caching.
- **GraphQL**: best when many screens need different slices of related data.
- **tRPC**: best when **one TypeScript team owns both client and server** (monorepo): end-to-end types, no schema or codegen.

## Interview answer
> I choose by clients and team structure. REST is the default for public APIs and many independent consumers, and it benefits fully from HTTP caching. GraphQL suits products with many screens and clients that need different shapes of interconnected data, at the cost of more server work and caching complexity. tRPC fits a single team writing both frontend and backend in TypeScript, giving type-safe function calls without a schema layer, but it couples the client to the server and isn't meant for public APIs.

## The analogy
Three ways to order food: a **printed menu** anyone can read (REST), a **build-your-own bowl counter** (GraphQL), and **cooking at home** where you're both the chef and the eater (tRPC).

## How it works
```compare
Choose || When
REST || Public API, many unknown clients, CDN caching matters, simple CRUD
GraphQL || Many screens/apps need different fields from connected data
tRPC || One TypeScript team, monorepo, internal API, fast iteration
```

- In the wild: GitHub offers both REST and GraphQL; Shopify's Storefront API is GraphQL; many TypeScript startups use tRPC internally.

## Common traps
- **"GraphQL is always better."** It adds server complexity and makes caching harder.
- **tRPC for a public API.** It's designed for clients that share your TypeScript code.
- **Choosing by hype.** Decide by who calls the API and who maintains it.

## See it yourself
Compare `https://api.github.com/users/torvalds` (REST) with the same data in GitHub's GraphQL Explorer: note the different shapes and request counts.

## Quick quiz
<details><summary>When is REST the best choice?</summary>

Public APIs, many different clients, simple resources and when HTTP/CDN caching is important.
</details>
<details><summary>What does tRPC give you?</summary>

End-to-end type safety between a TypeScript client and server without writing a schema or generating code.
</details>
<details><summary>Why might GraphQL be slower?</summary>

A single complex query can trigger many expensive resolvers, and responses are harder to cache.
</details>
