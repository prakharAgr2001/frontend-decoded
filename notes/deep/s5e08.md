## Key points
- **Infinite scroll** is great for browsing on phones, but the footer is unreachable, Back loses your place, and memory grows.
- **Numbered pages** are better for hunting, sharing a "page 3" URL, and SEO. **"Load more"** is a good middle ground.
- Build infinite scroll with an **IntersectionObserver** on a sentinel element, not scroll listeners.

## Interview answer
> Infinite scroll suits casual browsing feeds on mobile, while pagination suits goal-oriented search where users compare, share or return to specific pages, and it's easier to crawl. A load-more button gives user control without losing the footer. I implement infinite scroll with an IntersectionObserver watching a sentinel near the end of the list, with a generous rootMargin to prefetch, virtualize very long lists, and preserve loaded pages and scroll position so Back returns users to where they were.

## The analogy
A buffet conveyor belt versus a menu with pages. The belt keeps food coming while you're snacking, but if you leave and come back, finding the dish you saw earlier is hard.

## How it works
```compare
Infinite scroll || Numbered pages
Casual browsing, social feeds || Searching, comparing, admin tables
Footer unreachable || Footer always reachable
Back button can lose position || "Page 3" is a shareable URL
Memory grows as you scroll || Fixed memory per page
```

```jsx
function Feed() {
  const { data, fetchNextPage, hasNextPage, isFetchingNextPage } = useInfiniteQuery(/* … */);
  const sentinel = useRef(null);
  useEffect(() => {
    const io = new IntersectionObserver(([e]) => {
      if (e.isIntersecting && hasNextPage && !isFetchingNextPage) fetchNextPage();
    }, { rootMargin: '600px' });                 // start loading before the user hits the bottom
    if (sentinel.current) io.observe(sentinel.current);
    return () => io.disconnect();
  }, [hasNextPage, isFetchingNextPage, fetchNextPage]);
  return (<>{data?.pages.flatMap(p => p.items).map(i => <Post key={i.id} {...i} />)}<div ref={sentinel} /></>);
}
```

## Common traps
- **Back button sends users to the top** and refetches from page 1. Keep loaded pages in a cache and restore scroll position.
- **Unreachable footer** with important links. Move them elsewhere or use "Load more".
- **Thousands of DOM nodes** after long scrolling. Virtualize.

## See it yourself
Scroll far down Instagram or YouTube on the web, open a post, press Back: see whether your position is restored.

## Quick quiz
<details><summary>Why use IntersectionObserver for infinite scroll?</summary>

It fires only when the sentinel nears the viewport, without running code on every scroll event or forcing layout.
</details>
<details><summary>When are numbered pages better?</summary>

For search and comparison, shareable/bookmarkable pages, a reachable footer, and SEO.
</details>
<details><summary>How do you preserve position on Back?</summary>

Keep the loaded pages (query cache or URL) and restore the scroll offset instead of refetching from page 1.
</details>
