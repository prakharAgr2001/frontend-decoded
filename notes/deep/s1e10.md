## Key points
- **Reflow (layout):** something's **size or position** changed, so the browser recalculates geometry, then repaints and composites. Expensive.
- **Repaint:** only **looks** changed (colour, background, shadow), so it repaints and composites. Cheaper.
- **Composite-only:** `transform` and `opacity`. Cheapest: no layout, no paint.

## Interview answer
> Changing geometry properties like width, height, top or font-size triggers layout, then paint and composite, and layout can cascade to parents, siblings and children. Changing visual-only properties like color or background triggers paint and composite. Changing transform or opacity on a layer only triggers compositing, which runs on the GPU. So for animations and frequent updates I stick to transform and opacity.

## The analogy
Rearranging a classroom. **Reflow:** one desk gets bigger, so every desk in the row shifts and you re-measure the room. **Repaint:** you just change one desk's colour; nothing moves. **Composite:** you slide a transparent sheet with a drawing over the desks; the desks themselves are untouched.

## How it works
```compare
Triggers layout || Skips layout
width, height, padding, margin || color, background (paint only)
top, left, font-size || box-shadow, border-color (paint only)
adding/removing elements, changing text || transform (composite only)
reading offsetHeight right after a write || opacity (composite only)
```

```js
// Expensive: layout every frame
box.style.left = x + 'px';

// Cheap: composite only
box.style.transform = `translateX(${x}px)`;
```

- One reflow can spread: changing a child's height can resize its parent and push its siblings.
- Reading layout values (`offsetHeight`, `getBoundingClientRect()`) **right after** changing styles forces the browser to do layout immediately (next episode: layout thrashing).

## Common traps
- **"Repaint is free."** It's cheaper than layout, but painting large areas (big blurred shadows, full-page backgrounds) is still slow.
- **Forced synchronous layout.** Write a style, then read a size, in the same frame = a reflow right now.
- **`visibility` vs `display` toggles.** `display` changes trigger layout; `visibility` only repaints.

## See it yourself
DevTools → ⋮ → More tools → **Rendering** → tick **Paint flashing**. Green flashes show every area being repainted as you scroll and hover.

## Quick quiz
<details><summary>Does changing color trigger a reflow?</summary>

No. Color doesn't affect geometry, so only paint and composite run.
</details>
<details><summary>Which two properties can be animated without layout or paint?</summary>

`transform` and `opacity`, when the element is on its own compositor layer.
</details>
<details><summary>Why is reflow considered expensive?</summary>

Geometry depends on other elements, so a change can force recalculation of parents, siblings and children, and then everything affected must be repainted.
</details>
