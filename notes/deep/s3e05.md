## Key points
- **INP (Interaction to Next Paint)** = time from a **click, tap or key press** to the **next frame painted** on screen. Good ≤ 200 ms.
- It has three parts: **input delay** (main thread busy) + **processing** (your handlers) + **presentation delay** (style, layout, paint).
- It reflects roughly your **worst** interaction during the visit, not the average.

## Interview answer
> INP measures responsiveness across all clicks, taps and key presses during a page visit, and reports roughly the slowest one. Each interaction is input delay while the main thread is busy, then the event handlers' processing time, then the presentation delay until the next frame paints. To improve it I show visual feedback first and defer heavy work by yielding, for example with scheduler.yield, I break up long tasks, reduce rendering work, and move heavy computation off the main thread.

## The analogy
Pressing a lift button. INP isn't about how fast the lift arrives; it's about how fast the **button lights up** to say "got it". A button that lights up instantly feels responsive even if the lift takes a while.

## How it works
```steps
Input delay | main thread is busy with something else (long tasks)
Processing | your event handlers run
Presentation delay | style → layout → paint for the next frame
```

```js
button.addEventListener('click', async () => {
  button.classList.add('loading');                 // 1. instant feedback
  await (globalThis.scheduler?.yield?.() ?? new Promise(r => setTimeout(r)));   // 2. let it paint
  runExpensiveFilter();                            // 3. heavy work after
});
```

## Common traps
- **Scrolling and hovering don't count.** Only clicks, taps and keyboard input.
- **Lighthouse can't measure INP** (it doesn't interact). Use field data or record interactions yourself.
- **Huge re-renders** in React on a click are a classic INP problem: smaller components, transitions, virtualisation.

## See it yourself
DevTools → **Performance** panel → live metrics view shows INP as you click around, with a list of interactions and their timing breakdown.

Input delay, processing time, presentation delay.
</details>
<details><summary>Does scrolling affect INP?</summary>

No. Only clicks, taps and key presses are measured.
</details>
<details><summary>How can you improve INP without making the work faster?</summary>

Show feedback immediately, then yield to the browser so it paints before running the heavy work.
</details>
