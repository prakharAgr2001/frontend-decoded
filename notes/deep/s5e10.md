## Key points
- A **request waterfall** is when request 2 can't start until request 1 finishes. In DevTools it looks like a staircase.
- Each step costs a full round trip (often 100–300 ms on mobile).
- The classic React cause is **fetch-on-render**: the parent fetches, renders the child, and only then does the child start its fetch.

## Interview answer
> A waterfall happens when requests run one after another even though they don't need to, often because components fetch in effects: the parent's data must arrive before the child renders and starts its own fetch. Each level adds a round trip. I fix it by starting requests as early as possible, in route loaders, by hoisting fetches to the route level, or by prefetching, so it becomes fetch-then-render. When a request truly depends on another, I move that join to the server, in a single endpoint or BFF, where round trips are cheap.

## The analogy
A relay race where each runner waits for the previous one to finish before even standing up. If the legs don't depend on each other, everyone should run at the same time.

## How it works
```compare
Fetch-on-render (waterfall) || Fetch-then-render
Page renders → fetches user || Route loader starts user, orders and offers together
User arrives → renders <Orders> → fetches orders || All requests in flight at once
Orders arrive → renders <Offers> → fetches offers || Render when data is ready
3 round trips in a row || ~1 round trip
```

```jsx
// React Router: start all requests before rendering the route
export async function loader({ params }) {
  const [user, orders] = await Promise.all([
    fetch(`/api/users/${params.id}`).then(r => r.json()),
    fetch(`/api/users/${params.id}/orders`).then(r => r.json()),
  ]);
  return { user, orders };
}
```

## Common traps
- **Nested components each fetching in useEffect**: hidden waterfalls.
- **Lazy-loaded component that then fetches data**: chunk download + data fetch in sequence. Prefetch both.
- **Real dependencies** (need the user id first): join on the server in one endpoint.

## See it yourself
DevTools → **Network** → reload a slow page → look at the waterfall column: a staircase of requests that start only when the previous one ends.

Components start fetching only after they render, so nested components wait for their parents' data first.
