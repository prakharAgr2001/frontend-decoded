## Key points
- Server HTML is like a **picture** of the page: it looks right, but buttons don't work yet.
- **Hydration** = React runs your components again in the browser and **attaches event handlers to the existing DOM** (it doesn't rebuild it).
- It runs on the main thread, often as **one long task**, so taps during hydration wait.

## Interview answer
> After server rendering, the browser has static HTML but no event listeners or component state. Hydration loads the same component code on the client, renders the tree in memory, matches it against the existing DOM, and attaches event handlers and state instead of recreating nodes. It's called with hydrateRoot. Because it re-executes every component, it costs CPU time on the main thread, which delays interactivity on slow devices.

## The analogy
Adding water to instant noodles. The noodles (HTML) are already there and look like food, but you can't eat them until you add hot water (JavaScript) and wait.

## How it works
```steps
Server | renderToString(<App />) produces HTML
Browser paints | content visible, nothing clickable
Bundle loads | the same components arrive as JS
hydrateRoot | React renders in memory and walks the existing DOM
Attach handlers | onClick, state, effects: now it's interactive
```

```jsx
// server.js
import { renderToString } from 'react-dom/server';
const html = renderToString(<App />);

// client.js
import { hydrateRoot } from 'react-dom/client';
hydrateRoot(document.getElementById('root'), <App />);
```

## Common traps
- **"Hydration rebuilds the DOM."** It reuses the existing DOM; it does re-run every component, which is the expensive part.
- **`createRoot` instead of `hydrateRoot`** throws away the server HTML and re-renders from scratch.
- **Bigger trees = longer hydration.** Fewer client components means less to hydrate.

## See it yourself
DevTools → **Performance** with **CPU 4x slowdown** → reload an SSR site → look for a big scripting block after the first paint: that's hydration.

## Quick quiz
<details><summary>What does hydration actually do?</summary>

Re-runs components on the client to rebuild React's internal tree and attach event listeners and state to the server-rendered DOM.
</details>
<details><summary>Why can taps feel ignored right after an SSR page appears?</summary>

Hydration hasn't finished: there are no handlers yet, and the main thread may be busy hydrating.
</details>
<details><summary>Which React API hydrates a server-rendered root?</summary>

`hydrateRoot` from `react-dom/client`.
</details>
