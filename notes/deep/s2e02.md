## Key points
- In **client-side rendering (CSR)**, the server sends an almost empty HTML file plus a JS bundle. JavaScript builds the whole page in the browser.
- **Pros:** cheap static hosting, very fast navigation after the first load (feels like an app).
- **Cons:** slow first paint, and tools that don't run JS (link previews, some crawlers) see a blank page.

## Interview answer
> In CSR the server returns a minimal HTML shell with a root element and script tags. The browser downloads and executes the bundle, which fetches data and renders the UI into the DOM. It's simple to host on a CDN and great for app-like experiences after load, but first contentful paint is slow, especially on low-end devices, and anything that reads raw HTML, like social link previews, sees no content. It fits dashboards and logged-in tools more than public, SEO-sensitive pages.

## The analogy
A restaurant that hands you raw ingredients and a recipe card. Once you've learned the kitchen, cooking the next dish is quick. But the first meal takes a long time, and anyone peeking through the window just sees an empty table.

## How it works
```steps
Request the page | server returns index.html with <div id="root"></div>
Download the bundle | main.js, often hundreds of KB
Run React | components render in the browser
Fetch data | API calls, then render again with real content
Navigate | later pages need only data, no new HTML
```

```html
<!-- What the server actually sends in a CSR app -->
<body>
  <div id="root"></div>
  <script src="/assets/main.4f2a.js"></script>
</body>
```

## Common traps
- **SEO and link previews.** Google can run JS (sometimes later), but WhatsApp, LinkedIn and Slack previews read raw HTML only, so they show a blank card.
- **Loading spinners everywhere.** Every page that fetches after render shows a spinner first; consider skeletons or prefetching.
- **Bundle growth.** One big bundle makes every first visit slower. Split code by route.

## See it yourself
On any React app built with Vite or Create React App: **View Page Source** shows an empty `#root`. DevTools → **Elements** shows the full page that JS built.

## Quick quiz
<details><summary>Why does a CSR page's link preview show nothing?</summary>

Preview bots fetch the HTML without running JavaScript, and CSR HTML has no content, only an empty root element.
</details>
<details><summary>When is CSR a good choice?</summary>

Logged-in, highly interactive apps (dashboards, editors, internal tools) where SEO doesn't matter and users stay for long sessions.
</details>
<details><summary>View Source vs Elements panel: what's the difference in a CSR app?</summary>

View Source shows what the server sent (an empty shell). Elements shows the live DOM after JavaScript rendered the page.
</details>
