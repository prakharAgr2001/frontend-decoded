## Key points
- Redux has three ideas: **one store**, **actions describe what happened** (`{ type: 'cart/added', item }`), and **reducers are pure functions** `(state, action) → newState`.
- A minimal `createStore` is about 10 lines: keep state, run the reducer on dispatch, notify subscribers.
- Data flows **one way**: UI → dispatch → reducer → new state → subscribers re-render.

## Interview answer
> Redux keeps application state in a single store. Components dispatch plain action objects that describe events, and a pure reducer computes the next state from the current state and the action without mutating anything. After each dispatch the store notifies subscribers, which re-render with the new state. Because updates are pure and serializable, you get predictable behaviour and tooling like Redux DevTools with an action log and time-travel debugging.

## The analogy
A bank ledger. You never erase a balance; you write a new transaction (action), and the accountant (reducer) calculates the new balance from the old one. Anyone can replay the ledger to see how you got here.

## How it works
```js
function createStore(reducer, initialState) {
  let state = initialState;
  const subscribers = new Set();
  return {
    getState: () => state,
    subscribe: fn => (subscribers.add(fn), () => subscribers.delete(fn)),
    dispatch(action) {
      state = reducer(state, action);         // pure: returns a new object
      subscribers.forEach(fn => fn());        // notify the UI
    },
  };
}

function cartReducer(state = { items: [] }, action) {
  switch (action.type) {
    case 'cart/added': return { ...state, items: [...state.items, action.item] };
    case 'cart/removed': return { ...state, items: state.items.filter(i => i.id !== action.id) };
    default: return state;
  }
}
```

```steps
UI | dispatch({ type: 'cart/added', item })
Reducer | (state, action) → new state object
Store saves it | and notifies subscribers
UI re-renders | with the new state
```

## Common traps
- **Mutating state in a reducer** and returning the same object: `Object.is(prev, next)` is true, so the UI never updates and time travel breaks.
- **Side effects in reducers** (API calls, random IDs). Reducers must be pure; do effects in thunks or middleware.
- **Everything in Redux.** Server data belongs in a query cache.

## See it yourself
Install **Redux DevTools** and open any app that uses Redux: you'll see every action, the state diff, and a slider to time-travel.

## Quick quiz
<details><summary>What makes a reducer "pure"?</summary>

Same inputs always give the same output, no side effects, and it never mutates its arguments.
</details>
<details><summary>Why doesn't the UI update if the reducer mutates state?</summary>

The returned state is the same reference, so subscribers comparing references see no change.
</details>
<details><summary>Describe Redux's data flow.</summary>

UI dispatches an action → reducer computes new state → store saves it and notifies subscribers → UI re-renders.
</details>
