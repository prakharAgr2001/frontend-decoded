## Key points
- **`React.memo`** skips re-rendering a component if its props are shallowly equal. **`useMemo`** caches a computed value. **`useCallback`** keeps a function's identity stable.
- Memoization **isn't free**: it stores values and compares props on every render.
- **Inline objects and arrow functions break `memo`**, because they're new on every render.

## Interview answer
> React.memo prevents a component from re-rendering when its props are shallowly equal, useMemo caches the result of an expensive calculation between renders, and useCallback caches a function so its reference stays stable. They help only when the skipped work is expensive and the props really are stable, which usually means passing memoized objects and callbacks. Memoization adds memory and comparison overhead, so I apply it based on profiler evidence, not by default. useMemo is a performance hint, not a guarantee.

## The analogy
Keeping a photocopy of an answer sheet. Useful if the calculation is long and you check it often. Pointless if the answer takes two seconds to work out, and you still pay for the paper.

## How it works
```compare
Breaks memo || Keeps memo working
<Row style={{ color: 'red' }} /> || const style = useMemo(() => ({ color: 'red' }), [])
<Row onSelect={() => select(id)} /> || const onSelect = useCallback(() => select(id), [id])
Memo on a cheap component || Memo on a measured, expensive one
```

```jsx
const Row = React.memo(function Row({ item, onSelect }) {
  return <li onClick={() => onSelect(item.id)}>{item.name}</li>;
});

function List({ items }) {
  const [selected, setSelected] = useState(null);
  const onSelect = useCallback(id => setSelected(id), []);
  const sorted = useMemo(() => [...items].sort((a, b) => a.name.localeCompare(b.name)), [items]);
  return <ul>{sorted.map(i => <Row key={i.id} item={i} onSelect={onSelect} />)}</ul>;
}
```

## Common traps
- **Memoizing everything** adds overhead and makes code harder to read.
- **Relying on useMemo for correctness.** React may discard cached values; it's only an optimisation.
- **The React Compiler** now does much of this automatically (next episode).

## See it yourself
React DevTools → **Profiler** → record an interaction → **Ranked** view shows which components took the most time. Memoize those, then record again to compare.

## Quick quiz
<details><summary>Why does an inline object prop defeat React.memo?</summary>

A new object is created every render, so shallow comparison sees a different reference each time.
</details>
<details><summary>useMemo vs useCallback?</summary>

useMemo caches a computed value; useCallback caches a function reference (useCallback(fn, deps) ≈ useMemo(() => fn, deps)).
</details>
<details><summary>When is memoization worth it?</summary>

When profiling shows a component or calculation is expensive and it re-renders often with the same inputs.
</details>
