## Key points
- When several components ask for the same data at the same moment, **share the in-flight promise** instead of sending duplicate requests.
- React Query does this automatically per query key.
- **Dedup ≠ cache**: dedup shares a request **while it's in flight**; a cache keeps the answer **afterwards**.

## Interview answer
> Request deduplication makes concurrent callers for the same resource share one in-flight request. A simple implementation keeps a map from key to promise, returns the existing promise if one is pending, and removes it when it settles. Caching is different: it stores the result for later calls. Libraries like React Query and SWR do both by query key. In development, React StrictMode intentionally mounts components twice, so seeing a double fetch there is expected and doesn't happen in production.

## The analogy
Five people in a WhatsApp group asking "what time is the movie?" One person checks and replies to all, instead of five people calling the cinema.

## How it works
```js
const inFlight = new Map();

function dedupedFetch(url) {
  if (inFlight.has(url)) return inFlight.get(url);           // reuse the pending request
  const p = fetch(url).then(r => r.json()).finally(() => inFlight.delete(url));
  inFlight.set(url, p);
  return p;
}

// Header, sidebar and page all ask at once → one network request
dedupedFetch('/api/me'); dedupedFetch('/api/me'); dedupedFetch('/api/me');
```

```compare
Deduplication || Caching
Shares a request that's still in flight || Stores the result after it arrives
Gone as soon as the request settles || Lives until it expires or is evicted
Prevents duplicate concurrent calls || Prevents repeat calls later
```

## Common traps
- **Double fetch in development** is React StrictMode (mount → unmount → mount), not a bug. Production fetches once.
- **Forgetting to delete the key** on settle: later calls get the old promise forever (an accidental cache).
- **Different keys for the same data** (`/api/me` vs `/api/me?`) defeat dedup.

## See it yourself
Render three components that call `useQuery({ queryKey: ['me'] })` and check DevTools → **Network**: only one request for `/api/me`.
