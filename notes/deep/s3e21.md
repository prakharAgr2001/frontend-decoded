## Key points
- Third-party scripts (chat widgets, analytics, ads, A/B tools) run on **your main thread**: they cause long tasks (INP), late banners (CLS) and extra connections.
- **Measure first**: block them in DevTools and compare.
- Tame them: **facades** (fake button until clicked), **load after interaction**, self-host, or move them off the main thread (Partytown).

## Interview answer
> Third-party scripts compete with my own code for the main thread and the network, so they often cause the worst long tasks and layout shifts. I measure their impact by blocking them and comparing metrics, then decide per script: remove it, load it after the page is interactive or on first interaction, replace heavy embeds with a lightweight facade, reserve space for anything that renders, and in some cases run them in a web worker with a tool like Partytown. Async loading alone doesn't help, because the script still executes on the main thread.

## The analogy
Letting a guest cook in your kitchen during dinner rush. Even if they arrive quietly (async), once they start cooking they use your one stove.

## How it works
```compare
Default embed || Facade
Loads 500 KB chat widget on page load || Shows a lightweight "Chat" button image
Runs JS on your main thread at startup || Loads the real widget only on click
Hurts LCP and INP for everyone || Costs only the users who chat
```

```js
// Load the chat widget only when the user shows intent
chatButton.addEventListener('click', () => {
  const s = document.createElement('script');
  s.src = 'https://chat.example.com/widget.js';
  document.body.append(s);
}, { once: true });
```

## Common traps
- **"It's async, so it's fine."** async only avoids blocking HTML parsing; it still runs on your main thread.
- **Tag managers** quietly grow to dozens of scripts. Audit them regularly.
- **Embeds without reserved space** (YouTube, chat bubbles, cookie bars) cause CLS.

## See it yourself
DevTools → **Network** → right-click a third-party request → **Block request domain** → reload and compare the Performance trace. The Performance panel also has a **"3rd parties"** insight listing their cost.

## Quick quiz
<details><summary>Why doesn't async solve third-party performance?</summary>

It only prevents parser blocking; when the script runs, it still occupies the main thread.
</details>
<details><summary>What's a facade?</summary>

A lightweight static placeholder that looks like the widget and loads the real one only when the user interacts with it.
</details>
<details><summary>How do you measure one script's impact?</summary>

Block its domain in DevTools (or remove it in a test) and compare metrics with and without it.
</details>
