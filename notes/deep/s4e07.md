## Key points
- **Redux Toolkit (RTK)** is the official way to write Redux today. `createSlice` generates action types and action creators for you.
- Inside `createSlice` reducers you can "mutate" (`state.items.push(x)`) because **Immer** gives you a draft and produces a new immutable state.
- `configureStore` wires DevTools and adds dev checks for accidental mutation and non-serializable values. **RTK Query** adds a server-state cache.

## Interview answer
> Redux Toolkit removes Redux boilerplate. createSlice defines the initial state and reducers together and generates the action creators. Reducers are written with mutating syntax, but Immer records the changes on a draft and returns a new immutable state, so the Redux rules still hold. configureStore sets up DevTools and development checks. RTK Query handles fetching and caching server data. Redux is still a good fit for large apps with many writers and a need for logged, replayable changes, but it's often overkill for small apps.

## The analogy
Plain Redux is building furniture from raw planks. Redux Toolkit is the same furniture as a well-designed flat-pack kit: same result, far fewer screws and mistakes.

## How it works
```js
import { createSlice, configureStore } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] },
  reducers: {
    added(state, action) { state.items.push(action.payload); },           // Immer makes this safe
    removed(state, action) { state.items = state.items.filter(i => i.id !== action.payload); },
  },
});

export const { added, removed } = cartSlice.actions;     // generated action creators
export const store = configureStore({ reducer: { cart: cartSlice.reducer } });

// In a component: dispatch(added({ id: 7, name: 'Shoes' }))
```

## Common traps
- **"Mutation is allowed everywhere now."** Only inside `createSlice` / `createReducer`. Elsewhere you still must not mutate state.
- **Putting Dates, class instances or functions in state** triggers serializability warnings and breaks DevTools.
- **Using Redux for server data by hand.** Use RTK Query or React Query instead.

## See it yourself
Open Redux DevTools on an RTK app: action types look like `cart/added`, generated from the slice name and reducer name.

## Quick quiz
<details><summary>How can RTK reducers use `push` without breaking immutability?</summary>

Immer gives the reducer a draft proxy, records the changes, and produces a new immutable state object.
</details>
<details><summary>What does configureStore add over createStore?</summary>

DevTools setup, good default middleware (thunk), and dev checks for mutations and non-serializable values.
</details>
<details><summary>Is Redux still worth using?</summary>

For large apps with many contributors and complex shared state that benefits from a predictable, logged update flow, yes. For small apps, lighter stores or local state are simpler.
</details>
