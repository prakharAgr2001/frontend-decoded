## Key points
- For independent requests: **start them all, then await together** with `Promise.all`. Total time ≈ the slowest one, not the sum.
- `Promise.all` **rejects on the first failure** and you lose the successful results. `Promise.allSettled` gives a result for every request.
- `await a(); await b(); await c();` runs **one after another**. Create the promises first, then await.

## Interview answer
> When requests don't depend on each other I fire them concurrently and await them together, so the total time is about the slowest request. Promise.all is right when all results are required, because it rejects as soon as any fails. When partial results are useful, like dashboard widgets, I use Promise.allSettled, which returns the status and value or reason for each. Writing sequential awaits accidentally serializes requests, so I create the promises before awaiting them.

## The analogy
Ordering at a food court. You don't wait for your dosa before ordering juice: you order both at different counters, and you're done when the slower one is ready.

## How it works
```js
// Sequential: ~ 300 + 400 + 200 = 900 ms
const user = await getUser(); const orders = await getOrders(); const offers = await getOffers();

// Parallel: ~ 400 ms (the slowest)
const [user2, orders2, offers2] = await Promise.all([getUser(), getOrders(), getOffers()]);

// Partial results: one failure doesn't lose the others
const results = await Promise.allSettled([getUser(), getOrders(), getOffers()]);
results.forEach(r => r.status === 'fulfilled' ? show(r.value) : showError(r.reason));
```

```compare
Promise.all || Promise.allSettled
Rejects on the first failure || Never rejects
Use when every result is required || Use when partial results are useful
Good: checkout needs cart + address + price || Good: dashboard widgets
```

## Common traps
- **Sequential awaits by accident** in a loop or one after another.
- **Promise.all for optional data**: one failed widget blanks the whole page.
- **Hundreds of parallel requests**: browsers limit connections per host on HTTP/1.1 (about 6); batch or limit concurrency.

## See it yourself
DevTools → **Network** → compare the waterfall of sequential awaits (staircase) with Promise.all (bars starting together).

## Quick quiz
<details><summary>Three requests of 200, 500 and 300 ms in parallel take about how long?</summary>

About 500 ms, the slowest one.
</details>
<details><summary>Promise.all vs Promise.allSettled?</summary>

all rejects on the first failure; allSettled waits for all and reports each result's status.
</details>
<details><summary>Why is `await a(); await b();` slow?</summary>

b doesn't start until a has finished, so their times add up.
</details>
