## Key points
- If state should be **shareable, bookmarkable or reachable with Back**, put it in the **URL**: search, filters, sort, page, selected tab.
- Read and write it with `useSearchParams`, and treat the URL as the **single source of truth** (don't copy it into `useState`).
- Use **`replace`** while typing and **`push`** for committed choices. Never put secrets or personal data in the URL.

## Interview answer
> State that a user should be able to share, bookmark, refresh or navigate back to belongs in the URL, typically search queries, filters, sorting, pagination and selected tabs. I read it from the URL on every render instead of mirroring it in component state, which avoids sync bugs. While the user is typing I replace the history entry so Back isn't cluttered, and I push on committed changes. URL values are strings, so I parse and validate them, and I never put tokens or personal data there because URLs end up in logs, history and referrers.

## The analogy
A Google Maps link. Send it to a friend and they see exactly the same place, zoom and route. That only works because everything is in the URL, not in your phone's memory.

## How it works
```jsx
import { useSearchParams } from 'react-router-dom';

function ProductFilters() {
  const [params, setParams] = useSearchParams();
  const q = params.get('q') ?? '';
  const sort = ['price', 'rating'].includes(params.get('sort')) ? params.get('sort') : 'rating';  // validate
  const page = Math.max(1, Number(params.get('page')) || 1);

  const update = (key, value, replace = false) => {
    const next = new URLSearchParams(params);
    value ? next.set(key, value) : next.delete(key);
    if (key !== 'page') next.delete('page');           // new filter → back to page 1
    setParams(next, { replace });
  };

  return (<>
    <input value={q} onChange={e => update('q', e.target.value, true)} />   {/* replace while typing */}
    <select value={sort} onChange={e => update('sort', e.target.value)}>    {/* push on commit */}
      <option value="rating">Top rated</option><option value="price">Price</option>
    </select>
  </>);
}
```

## Common traps
- **Copying URL params into useState** creates two sources of truth that drift.
- **Pushing on every keystroke** fills history: Back goes through every letter.
- **Secrets or personal data in the URL** leak via logs, browser history, referrer headers and screenshots.

## See it yourself
On Amazon or Flipkart, apply filters, then copy the URL into a private window: the same results appear. Press Back to see how they handle history.

## Quick quiz
<details><summary>What kind of state should live in the URL?</summary>

Anything shareable, bookmarkable or reachable with Back: search, filters, sort, page, selected tab, open item ID.
</details>
<details><summary>When do you use replace instead of push?</summary>

For transient updates like typing, so each keystroke doesn't create a history entry.
</details>
<details><summary>What should never go in a URL?</summary>

Secrets, tokens, passwords and personal data, plus huge objects and purely ephemeral UI state.
</details>
