## Key points
- **Optimistic UI**: update the screen **as if the request already succeeded**, send it, and **fix things only if it fails**.
- It makes actions feel instant even on slow networks.
- Use it for likes, toggles, reordering and chat messages. **Not** for payments or anything where a false "success" would hurt the user.

## Interview answer
> With optimistic updates I immediately apply the expected result to the UI or cache, then send the mutation in the background. If it fails, I roll back and inform the user. In React Query that's done in onMutate: cancel in-flight queries for that key, snapshot the current data, and write the optimistic value with setQueryData. React 19 also has useOptimistic for showing a temporary value while an action is running. It's ideal for high-success, low-risk actions, and I avoid it for payments, inventory-limited purchases or anything with serious consequences.

## The analogy
A waiter who writes "coffee: served" on your bill the moment you order, because the café almost never runs out. If the machine breaks, they come back, apologise and fix the bill.

## How it works
```steps
User taps Like | heart turns red instantly (cache updated)
Request sent | in the background
Success | nothing visible changes
Failure | roll back the heart and show "Couldn't like, try again"
```

```jsx
const qc = useQueryClient();
const like = useMutation({
  mutationFn: id => fetch(`/api/posts/${id}/like`, { method: 'PUT' }),
  onMutate: async id => {
    await qc.cancelQueries({ queryKey: ['post', id] });            // stop old data overwriting ours
    const prev = qc.getQueryData(['post', id]);
    qc.setQueryData(['post', id], p => ({ ...p, liked: true, likes: p.likes + 1 }));
    return { prev };
  },
  onError: (err, id, ctx) => qc.setQueryData(['post', id], ctx.prev),   // rollback (next episode)
  onSettled: (data, err, id) => qc.invalidateQueries({ queryKey: ['post', id] }),
});
```

## Common traps
- **Not cancelling in-flight refetches**: an older response arrives and overwrites the optimistic value.
- **Optimistic payments or orders.** False success is worse than a short wait.
- **No failure message.** Silent rollbacks confuse users.

## See it yourself
On Instagram or X, turn on airplane mode and tap Like: the heart fills instantly, then reverts or shows an error when the request fails.

## Quick quiz
<details><summary>What's the first thing to do in onMutate?</summary>

Cancel in-flight queries for that key so they can't overwrite the optimistic update.
</details>
<details><summary>Give two good and two bad use cases.</summary>

Good: likes, toggles, reordering, sending chat messages. Bad: payments, buying the last item in stock.
</details>
<details><summary>What does React 19's useOptimistic do?</summary>

Shows a temporary optimistic value while an async action runs, automatically reverting to the real state when it finishes.
</details>
