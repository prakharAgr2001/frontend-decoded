## Key points
- **Blog → SSG** (plus ISR and islands): fast, cheap, mostly static.
- **Amazon-style store → SSR / ISR**: content visible fast for users and search engines, then JS makes it interactive.
- **Gmail-style app → CSR + client routing**: slow first load, instant afterwards.
- Modern tools (streaming, server components, server actions, edge, resumability) all aim at the same goal: **less work on the user's phone without losing interactivity.**

## Interview answer
> There's no single best rendering strategy. Content sites like blogs fit static generation with incremental regeneration and a few interactive islands. Commerce and media sites benefit from server rendering or ISR for fast first paint and SEO, followed by hydration. Long-lived apps like email clients accept a slower first load for an app-like experience with client-side rendering and routing. Newer techniques such as streaming SSR, server components and resumability exist to reduce how much JavaScript the user's device must download and execute.

## The analogy
Choosing transport: walking for 500 metres (SSG), an auto for a few kilometres (SSR), and a car you own for daily long commutes (CSR). The right choice depends on the trip, not on which vehicle is "best".

## How it works
```compare
Strategy || Best for
SSG / ISR || Blogs, docs, marketing, product listings
SSR / streaming SSR || Personalised or fast-changing public pages
CSR + client routing || Logged-in apps used for long sessions
Islands / RSC / resumability || Ship less JS on mostly-content pages
```

## Common traps
- **Choosing by trend.** Pick by page needs: SEO, personalisation, freshness, interactivity.
- **Ignoring the device.** Most users are on mid-range phones; JS cost matters more than server speed.
- **Forgetting caching.** Many "SSR is slow" problems are really "nothing is cached".

## See it yourself
Pick three sites you use daily (a blog, a shop, an email app). Compare **View Source** and DevTools **Performance** filmstrips with CPU throttling, and guess the strategy each uses.

## Quick quiz
<details><summary>Why does Gmail accept a slow first load?</summary>

Users stay for long sessions, and after the first load every action is instant because only data is fetched. SEO doesn't matter for a private inbox.
</details>
<details><summary>What's the common goal of streaming, RSC and resumability?</summary>

Reduce the work and JavaScript the user's device has to do, while keeping the page fast to show and interactive.
</details>
<details><summary>Name the strategy: same for everyone, changes daily, needs SEO.</summary>

ISR (or SSG with frequent rebuilds).
</details>
