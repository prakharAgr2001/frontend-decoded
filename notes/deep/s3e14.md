## Key points
- **Tree shaking**: the bundler follows imports from your entry file, **keeps exports that are used, and drops the rest**.
- It needs **ES modules** (`import`/`export`), which are static. CommonJS `require()` usually can't be shaken.
- `import _ from 'lodash'` pulls in about 70 KB; `import { debounce } from 'lodash-es'` pulls in only what you use.

## Interview answer
> Tree shaking is dead-code elimination based on the static structure of ES module imports and exports. The bundler marks which exports are actually used and removes the unused ones during minification. It fails with CommonJS modules, with code that has side effects the bundler must keep, with dynamic property access, and with barrel files that re-export everything. Marking packages as side-effect-free in package.json and importing specific functions helps it work.

## The analogy
Packing for a trip by following a checklist of what you'll actually wear. Anything not on the list stays in the cupboard. But if an item is glued to something you need (side effects), it comes along too.

## How it works
```compare
Shakes poorly || Shakes well
const _ = require('lodash') || import { debounce } from 'lodash-es'
import * as utils from './utils' with dynamic access || named imports used directly
Barrel file: export * from './everything' || import from the specific file
Package with side effects || "sideEffects": false in package.json
```

```json
// package.json of your library
{ "sideEffects": false }
// or list files that DO have side effects:
{ "sideEffects": ["*.css", "./src/polyfills.js"] }
```

## Common traps
- **Barrel files** (`index.js` with `export * from …`) can make the bundler keep far more than you use.
- **CSS imports are side effects.** Marking everything side-effect-free can drop your CSS.
- **Only works in production builds** with minification on; dev bundles keep everything.

## See it yourself
Build your app and open a bundle analyzer (e.g. `vite-bundle-visualizer` or `webpack-bundle-analyzer`). Look for whole libraries where you only use one function.

## Quick quiz
<details><summary>Why does tree shaking need ES modules?</summary>

ES imports/exports are static, so the bundler can know what's used at build time. require() is dynamic and evaluated at runtime.
</details>
<details><summary>What does "sideEffects": false tell the bundler?</summary>

That importing a module has no effect besides its exports, so unused modules can be dropped completely.
</details>
<details><summary>Give two reasons unused code might stay in the bundle.</summary>

CommonJS modules, side effects, barrel re-exports, or dynamic property access on a namespace import.
</details>
