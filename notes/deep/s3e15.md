## Key points
- **100 KB of JS costs far more than 100 KB of image**: JS must be downloaded, **parsed, compiled and executed** on the main thread.
- **Measure first** (bundle analyzer), then cut: replace heavy libraries, drop unneeded polyfills, dedupe versions, use the platform.
- "200 KB gzipped" is around 700 KB for the browser to parse. Compression saves network, **not CPU**.

## Interview answer
> JavaScript is the most expensive asset because after downloading it has to be parsed, compiled and executed on the main thread, which hurts interactivity on slow devices. I start with a bundle analyzer to find the biggest dependencies, then replace heavy libraries with lighter ones or native APIs, remove unnecessary polyfills, dedupe multiple versions of the same package, and code-split the rest. I check package costs before adding them, for example with bundlephobia.

## The analogy
Luggage weight vs assembly time. An image is a sealed box: carry it and you're done. JavaScript is flat-pack furniture: carrying it is only the start, you still have to assemble it before you can use it.

## How it works
```compare
Heavy choice || Lighter option
moment (~70 KB) || date-fns, or the built-in Intl API
Whole lodash || lodash-es named imports, or native array methods
Big modal library || native <dialog>
axios everywhere || fetch
Polyfills for old browsers || only what your targets need
```

```js
// Built into every modern browser, zero KB
new Intl.DateTimeFormat('en-IN', { dateStyle: 'medium' }).format(new Date());
new Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' }).format(1999);
```

## Common traps
- **Judging by gzipped size.** The browser parses the uncompressed size.
- **Two versions of the same library** (e.g. React-dependent packages pinning different versions) double the cost. Check `npm ls <pkg>`.
- **Adding a dependency for one function.** Check its cost first.

## See it yourself
Run a bundle analyzer on your build. Then DevTools → **Performance** with CPU 4x slowdown → look at the "Evaluate Script" and "Compile" blocks for your main bundle.

## Quick quiz
<details><summary>Why is JS more expensive than an image of the same size?</summary>

JS must be parsed, compiled and executed on the main thread after downloading; images are decoded mostly off the main thread.
</details>
<details><summary>Does gzip reduce parse time?</summary>

No. It reduces transfer size; the browser still parses the full uncompressed code.
</details>
<details><summary>First step to shrink a large bundle?</summary>

Measure with a bundle analyzer to find the biggest contributors before changing anything.
</details>
