## Key points
- A **selector** picks just the slice of store state a component needs. After every update, the store re-runs it, and the component re-renders **only if the result changed** (`===`).
- Selectors that build new arrays or objects (`filter`, `map`, `{...}`) return **new references every time**, so the component always re-renders.
- Fix with **memoized selectors** (`createSelector`), separate selectors, or shallow comparison.

## Interview answer
> A selector maps store state to the data a component needs. Libraries like React Redux and Zustand run selectors after each update and compare the result with the previous one by reference, so components re-render only when their slice changes. Selectors that derive new arrays or objects return a new reference each time and defeat this, so I memoize them with createSelector, which recomputes only when inputs change, or use shallow equality. Selectors are also the natural place for derived data like totals and filtered lists.

## The analogy
A newspaper subscription for just the sports page. You only get a delivery when the sports page changes, unless the printer reprints a fresh copy every day even when nothing changed (a new reference), and then you get a delivery every day anyway.

## How it works
```compare
Re-renders every time || Re-renders only when needed
s => s.todos.filter(t => t.done) || createSelector([s => s.todos], todos => todos.filter(t => t.done))
s => ({ name: s.user.name, age: s.user.age }) || two selectors, or useShallow / shallowEqual
```

```js
import { createSelector } from '@reduxjs/toolkit';

const selectTodos = s => s.todos;
export const selectDoneTodos = createSelector([selectTodos], todos => todos.filter(t => t.done));
export const selectDoneCount = createSelector([selectDoneTodos], done => done.length);

// Component
const doneCount = useSelector(selectDoneCount);
```

## Common traps
- **Inline filtering in `useSelector`** returns a new array each time: constant re-renders.
- **One memoized selector shared by components with different arguments** keeps recomputing; create one per instance.
- **Selecting the whole state** (`s => s`) re-renders on any change.

## See it yourself
React DevTools → **Highlight updates**: a component with a non-memoized filter selector flashes on every store update, even unrelated ones.

## Quick quiz
<details><summary>How does a store decide whether to re-render a component?</summary>

It re-runs the component's selector after each update and compares the new result to the previous one by reference.
</details>
<details><summary>Why does `s => s.items.filter(...)` re-render every time?</summary>

filter returns a new array reference on every call, so the comparison always sees a change.
</details>
<details><summary>What does createSelector do?</summary>

Memoizes a derived value: it recomputes only when its input selectors return new values.
</details>
