## Key points
- **Debounce** = run the function **once, after the user stops** for a set time (e.g. 300 ms of quiet).
- Use it for search-as-you-type, autosave, and window resize recalculations.
- It reduces calls, but it **doesn't fix race conditions**: an older response can still arrive after a newer one.

## Interview answer
> Debouncing delays a function until a burst of events has stopped for a given wait time. Each new event clears the pending timer and starts a new one, so the function runs only once after the last event. It's ideal for search inputs, autosave and resize handling. It reduces work and requests, but responses can still arrive out of order, so I also cancel stale requests with AbortController or ignore responses that don't match the latest query.

## The analogy
A lift door. Every time someone else walks in, the door timer restarts. The door closes only after nobody has entered for a few seconds.

## How it works
```steps
User types "r" | start a 300 ms timer
Types "re" | cancel the timer, start again
Types "react" | cancel, start again
Stops typing for 300 ms | function runs once, with "react"
```

```js
function debounce(fn, wait = 300) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), wait);
  };
}

let controller;
const search = debounce(async q => {
  controller?.abort();                         // cancel the previous request
  controller = new AbortController();
  const res = await fetch(`/api/search?q=${encodeURIComponent(q)}`, { signal: controller.signal });
  render(await res.json());
}, 300);

input.addEventListener('input', e => search(e.target.value));
```

## Common traps
- **Race conditions remain.** Abort old requests or check the query when the response arrives.
- **Creating a new debounced function on every React render** resets it each time. Create it once (`useMemo`/`useRef`).
- **Debouncing visual feedback.** Debounce the expensive work, not the UI that should respond instantly.

## See it yourself
Type in a search box with DevTools → **Network** open: without debounce you see a request per keystroke; with it, one request after you pause.

## Quick quiz
<details><summary>When does a debounced function run?</summary>

After no new calls have happened for the wait period, once, with the latest arguments.
</details>
<details><summary>Why use AbortController with debounced search?</summary>

To cancel older in-flight requests so a slow, stale response can't overwrite newer results.
</details>
<details><summary>Debounce vs throttle in one line?</summary>

Debounce runs once after activity stops; throttle runs at most once per interval while activity continues.
</details>
