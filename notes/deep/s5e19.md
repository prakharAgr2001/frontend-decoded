## Key points
- A suspending component shows the **nearest `<Suspense fallback>`** until everything inside it is ready.
- **One boundary** for the whole page waits for the **slowest** part. **One per component** causes "popcorn" loading and jumps.
- Group sensibly: critical content first, its own boundary for heavy parts, below-the-fold content together. Pair each Suspense boundary with an ErrorBoundary.

## Interview answer
> Suspense boundaries define loading states: when any component inside suspends, React shows the nearest boundary's fallback until all its children are ready. With streaming SSR each boundary can be sent separately, and with selective hydration each hydrates independently. Boundary placement is a design decision. One large boundary delays everything until the slowest request finishes, while too many tiny boundaries make the page pop in piece by piece with layout shifts. I group related content and place error boundaries alongside. Fetching in useEffect never suspends, so I use framework loaders, the use API or suspense-enabled query hooks.

## The analogy
Serving a wedding meal. One big curtain until every dish is ready means everyone waits for dessert. Serving each item the moment it's ready means plates landing randomly. Serving by course is the sweet spot.

## How it works
```jsx
<Layout>
  <ProductHeader />                                  {/* critical, fast */}
  <ErrorBoundary fallback={<ReviewsError />}>
    <Suspense fallback={<ReviewsSkeleton />}>
      <Reviews />                                    {/* slow, own boundary */}
    </Suspense>
  </ErrorBoundary>
  <Suspense fallback={<BelowFoldSkeleton />}>
    <SimilarProducts /><RecentlyViewed />            {/* below the fold, grouped */}
  </Suspense>
</Layout>
```

```compare
Boundary layout || Effect
One for the whole page || Waits for the slowest request
One per component || Popcorn loading, layout jumps
Grouped by section || Fast critical content, calm loading
```

## Common traps
- **`useEffect` fetching never triggers Suspense.** Use `use(promise)`, a framework loader, or `useSuspenseQuery`.
- **Suspense without an error boundary**: a failed request has nowhere to go.
- **Fallbacks with different sizes** than the content cause layout shift.

## See it yourself
In a Next.js app, add a `loading.js` (a Suspense boundary) to a route and throttle the network: the fallback shows, then content streams into place.

## Quick quiz
<details><summary>What does a Suspense boundary wait for?</summary>

All suspended components inside it; it shows its fallback until they're all ready.
</details>
<details><summary>What's the downside of one boundary per component?</summary>

Content pops in piece by piece, causing visual noise and layout shifts.
</details>
<details><summary>Why doesn't my useEffect fetch show the Suspense fallback?</summary>

Effects run after render and don't suspend; Suspense needs data read during render via a suspense-enabled source.
</details>
