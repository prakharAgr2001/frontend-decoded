## Key points
- The **uncanny valley**: the page is **visible** but **not yet interactive** because JS is still loading or hydrating.
- **FCP** = first time you see something. **TTI** = when it reliably responds. **TBT** = how long the main thread was blocked in between.
- In the field, this shows up as bad **INP** (slow response to taps).

## Interview answer
> With SSR the page can paint early, but it isn't usable until JavaScript has downloaded and hydrated. That gap between First Contentful Paint and Time to Interactive is where users tap and nothing happens, which is frustrating and causes rage clicks. In lab tools it shows as high Total Blocking Time; in real-user data it appears as poor INP. Reducing JavaScript, splitting hydration, and deferring non-critical scripts shrink that gap.

## The analogy
A shop with the lights on and products on display, but the doors are still locked. People can see everything and keep pushing the door.

## How it works
```steps
FCP | first text or image appears
Long tasks | JS parses, runs, hydrates (main thread busy)
Taps queue up | nothing happens yet
TTI | main thread quiet, handlers attached
```

- Lab metric to watch: **Total Blocking Time** (time above 50 ms in each long task between FCP and TTI).
- Field metric to watch: **INP**, since that's what real users experience.

## Common traps
- **Green Lighthouse score ≠ happy users.** Lighthouse tests one simulated device; real users on cheap phones may have much worse INP.
- **Showing buttons before they work** with no feedback. Consider disabled states or making critical forms work without JS.
- **Third-party scripts** (chat widgets, analytics) often cause the biggest long tasks.

## See it yourself
DevTools → **Performance** → CPU **4x slowdown** → reload with Screenshots on. Compare the first screenshot with content to where the long tasks end: that's your uncanny valley.

## Quick quiz
<details><summary>What's the difference between FCP and TTI?</summary>

FCP is when content first appears; TTI is when the page reliably responds to input. The gap between them is the uncanny valley.
</details>
<details><summary>What does Total Blocking Time measure?</summary>

The sum of the portions of long tasks over 50 ms between FCP and TTI: how long input would have been blocked.
</details>
<details><summary>Which Core Web Vital reflects this problem for real users?</summary>

INP (Interaction to Next Paint).
</details>
