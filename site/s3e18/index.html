Responsive images

Key points

  • srcset lists image files with their widths; sizes tells the browser how wide the image will be displayed. The browser picks the smallest file that still looks sharp, including screen density (DPR).
  • <picture> lets you offer modern formats (AVIF/WebP) with a JPEG fallback, or different crops per screen (art direction).
  • Without sizes, the browser assumes the image is full screen width (100vw) and often downloads the biggest file.

Interview answer

For responsive images I provide multiple widths in srcset and describe the rendered width with sizes, so the browser can choose the smallest file that's sharp for the device's pixel density. I use the picture element to serve AVIF or WebP with a JPEG fallback, and for art direction when mobile needs a different crop. I always set width and height to avoid layout shift, and I serve images from an image CDN that resizes and converts automatically.

The analogy

Ordering a pizza by table size. srcset is the menu of sizes; sizes tells the waiter how big your table is. Without that, they bring the family size to a table for one.

How it works

<picture>
  <source type="image/avif" srcset="/p-400.avif 400w, /p-800.avif 800w, /p-1600.avif 1600w"
          sizes="(max-width: 600px) 100vw, 50vw">
  <img src="/p-800.jpg"
       srcset="/p-400.jpg 400w, /p-800.jpg 800w, /p-1600.jpg 1600w"
       sizes="(max-width: 600px) 100vw, 50vw"
       width="800" height="600" alt="Blue running shoes">
</picture>

Common traps

  • Missing sizes → the browser assumes 100vw and downloads the largest candidate.
  • Using x descriptors for fluid images. 1x/2x suits fixed-size images like logos; use w for layout-dependent ones.
  • Forgetting width/height causes layout shift.

See it yourself

DevTools → Elements → hover an <img>: it shows rendered size vs intrinsic size. If intrinsic is much bigger, you're over-downloading. Lighthouse flags this as "Properly size images".

Quick quiz

What does sizes tell the browser?

How wide the image will be displayed at different viewport widths, so it can choose the right srcset file before layout.

Why use picture instead of just img?

To offer modern formats with fallbacks (AVIF/WebP → JPEG) or different crops for different screens.

A phone (DPR 3) shows an image 360 px wide. Which width should it download?

About 1080 px (360 × 3), so the closest srcset candidate at or above that.

  • srcset (files + w widths) + sizes (display width) → browser picks the smallest sharp file, including DPR. <picture> for AVIF/WebP + JPEG fallback and art direction (media).
  • See it: Elements → hover <img>: rendered vs intrinsic size; Lighthouse "Properly size images". Trap: no sizes → assumes 100vw → biggest file.
