Key points

  • Normal HTTP is request → response: the server can't speak first. "Real-time" means the server can push the moment something happens.
  • There are five ways to get updates: short polling, long polling, Server-Sent Events (SSE), WebSockets, WebRTC.
  • Pick by who talks and how often, not by hype: a badge can poll, AI answers stream over SSE, chat uses WebSockets.

Interview answer

HTTP is client-initiated, so to get updates the client either asks repeatedly or keeps a channel open that the server can write to. Short polling asks on a timer; long polling holds each request open until there's news; Server-Sent Events keep one HTTP response open for server-to-client messages; WebSockets upgrade to a full-duplex connection; and WebRTC connects browsers directly for media and data. I choose based on direction, frequency and latency needs rather than defaulting to WebSockets.

The analogy

Waiting for a parcel. Short polling: you check the door every 5 minutes. Long polling: you stand at the door until it comes, then go back and wait again. SSE: the courier rings your bell whenever something arrives. WebSockets: an open phone line you can both talk on. WebRTC: you and your friend talk directly without the post office in between.

Common traps

  • "Real-time means WebSockets." Often SSE or even polling is simpler and enough.
  • Ignoring direction. If only the server sends, a two-way socket is extra complexity.
  • Forgetting reconnection. Every long-lived connection drops eventually.

See it yourself

Open WhatsApp Web → DevTools → Network → filter WS → click the connection → Messages: received frames in red (down arrow) and sent frames in green (up arrow).

Quick quiz

Why can't plain HTTP push data to the client?

It's request-response: the server can only reply to a request the client made.

Name the five real-time transports.

Short polling, long polling, Server-Sent Events, WebSockets, WebRTC.

Which would you use to stream an AI chatbot's answer?

Server-Sent Events (server → client streaming over plain HTTP).
