Key points

  • Controlled inputs keep their value in React state (value + onChange): a re-render on every keystroke. Uncontrolled inputs let the DOM hold the value; you read it on submit with FormData or refs.
  • Form state = values, touched, dirty, errors, isSubmitting. Libraries like React Hook Form use refs and only re-render what subscribes.
  • Validation UX: validate on blur or submit first, then on change once there's an error ("reward early, punish late").

Interview answer

Controlled inputs store the value in React state, which makes it easy to transform or validate on every change but re-renders on each keystroke. Uncontrolled inputs keep the value in the DOM and read it on submit, which is lighter. For non-trivial forms I use React Hook Form with a schema validator like zod: it registers inputs via refs, tracks touched, dirty and error state, and re-renders only subscribed fields. I validate on blur or submit first and switch to validating on change once a field has an error. React 19 also adds form actions and useActionState.

The analogy

Filling a paper form at a bank. A controlled form is a clerk reading every letter as you write. An uncontrolled form is the clerk reading the whole form when you hand it in. Good clerks don't shout "wrong!" while you're still writing your PIN code.

How it works

import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({ email: z.string().email(), pincode: z.string().regex(/^\d{6}$/) });

function AddressForm({ onSave }) {
  const { register, handleSubmit, formState: { errors, isSubmitting } } =
    useForm({ resolver: zodResolver(schema), mode: 'onTouched' });   // validate on blur, then on change
  return (
    <form onSubmit={handleSubmit(onSave)}>
      <input {...register('email')} />{errors.email && <p>Enter a valid email</p>}
      <input {...register('pincode')} />{errors.pincode && <p>6-digit pincode</p>}
      <button disabled={isSubmitting}>Save</button>
    </form>
  );
}

Common traps

  • Input loses focus on every keystroke: a component defined inside another component gets a new type each render, so React remounts it. Define components outside.
  • Errors shown while the user is still typing for the first time feel aggressive.
  • Validating only on the client. The server must validate too.

See it yourself

React DevTools → Highlight updates → type in a controlled form vs a React Hook Form form: the controlled one flashes on every key.

Quick quiz

Controlled vs uncontrolled input?

Controlled: React state is the source of truth and the input re-renders on change. Uncontrolled: the DOM holds the value; you read it when needed (FormData/refs).

Why does an input lose focus on every keystroke?

Its component is defined inside another component (or has an unstable key), so React sees a new component type each render and remounts it.

What's "reward early, punish late"?

Don't show errors until the user leaves the field or submits; once an error is shown, clear it as soon as the input becomes valid.

  • Controlled (value + onChange, a render per keystroke) vs uncontrolled (DOM holds value, FormData / refs on submit).
  • Form state = values, touched, dirty, errors, isSubmitting. React Hook Form: register (refs), schema resolver (zod), subscribe-only re-renders.
  • Errors: validate on blur/submit first, then on change ("reward early, punish late"). React 19: useActionState, <form action>.
  • Trap: input loses focus each keystroke → component defined inside another (new type every render). Define outside, stable keys.
