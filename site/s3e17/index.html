Key points

  • Revision episode: four interview questions on loading and bundles.
  • Know when each kind of script runs, the difference between resource hints, why tree shaking sometimes fails, and a plan for cutting a huge bundle.

Interview answer

For loading, I keep the critical path short: inline critical CSS, defer scripts, preconnect to key origins and preload late-discovered critical files. For bundles, I measure first, split by route and feature, replace heavy dependencies, make sure tree shaking works with ES modules, ship minified and Brotli-compressed code, and protect it with a size budget in CI.

Quick quiz

When does each script type run: plain, async, defer, module?

Plain: blocks parsing, runs immediately. async: downloads in parallel, runs on arrival, no order. defer: downloads in parallel, runs after parsing in order. module: deferred by default.

preconnect vs preload vs prefetch?

preconnect warms up a connection to an origin. preload fetches a resource needed by this page at high priority. prefetch fetches a resource for a future navigation at low priority.

Why might tree shaking keep code you don't use?

CommonJS modules, side effects (or missing "sideEffects" config), barrel files that re-export everything, or dynamic access to a namespace import.

How would you cut a 1.5 MB bundle?

Measure with a bundle analyzer → split by route and lazy-load heavy features → replace or remove heavy dependencies and polyfills, dedupe versions → make sure tree shaking works → minify + Brotli → add a size budget in CI so it doesn't grow back.
