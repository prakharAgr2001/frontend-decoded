Interview answer

For runtime performance I reduce how often work runs with debounce, throttle or requestAnimationFrame, render less with virtualization, avoid unnecessary React renders by fixing component structure before memoizing, and keep interactions under 200 ms by giving instant feedback and then chunking, deferring or offloading the heavy work.

Quick quiz

Debounce vs throttle, with examples?

Debounce runs once after events stop (search box, autosave). Throttle runs at most once per interval during events (scroll progress, drag). For visuals use requestAnimationFrame; for visibility use IntersectionObserver.

How would you render a table with 10,000 rows?

Virtualize it (render visible rows + overscan), or use content-visibility: auto, or paginate. Mention the trade-offs: find-in-page, accessibility, variable row heights.

Why does a React component re-render, and how do you reduce it?

State change, context change, or parent re-render. Reduce by moving state down, passing children as props, splitting context, memoizing where profiling shows benefit, or using the React Compiler.

A click handler takes 400 ms. How do you fix INP?

Show feedback immediately, then yield (scheduler.yield) before heavy work; chunk the work; move pure computation to a Web Worker; mark non-urgent React updates as transitions; reduce the work itself (virtualize, cache).
