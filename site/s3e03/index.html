Key points

  • LCP (Largest Contentful Paint) = time until the largest image or text block in the viewport is painted. Good ≤ 2.5 s.
  • Candidates: <img>, a video's poster, a CSS background image, a big block of text.
  • LCP splits into 4 parts: TTFB → load delay → load duration → render delay. The usual culprit is load delay: the image is discovered late.

Interview answer

LCP measures when the largest visible content element finishes rendering. I break it into time to first byte, resource load delay, resource load duration and element render delay. Most slow LCPs come from the hero image being discovered late, for example because it's set in CSS, injected by JavaScript or lazy-loaded. Fixes are putting the image directly in the HTML, adding fetchpriority high or a preload, serving a properly sized modern format from a CDN, and keeping render-blocking resources small.

The analogy

A stage show where the main actor arrives late. The stage, lights and curtains were ready early, but the audience feels the show started only when the star walked on.

How it works

<!-- Discoverable early, high priority, NOT lazy -->
<img src="/hero-1200.avif" width="1200" height="600" fetchpriority="high" alt="New collection">

Common traps

  • loading="lazy" on the hero image delays it until layout. Never lazy-load above-the-fold images.
  • Hero as a CSS background or rendered by client JS: the preload scanner can't see it early.
  • Huge images. A 3000 px JPEG on a phone wastes seconds; serve responsive sizes in AVIF/WebP.

See it yourself

DevTools → Performance → record a page load → the LCP marker shows which element it was; the LCP breakdown insight shows the 4 sub-parts.

Quick quiz

What elements can be the LCP element?

Images (including SVG images inside, video posters, CSS background images) and block-level text elements in the viewport.

The hero image downloads in 200 ms but LCP is 4 s. Where do you look?

TTFB, load delay (the image was found late) and render delay (render-blocking CSS/JS).

Why does lazy-loading the hero hurt LCP?

Lazy images wait until layout confirms they're near the viewport, so the download starts much later.
