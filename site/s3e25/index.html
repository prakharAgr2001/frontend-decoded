Virtualization

Key points

  • Virtualization renders only the rows you can see (plus a few extra), not all 10,000.
  • A tall spacer keeps the scrollbar correct, and rows are recycled as you scroll.
  • Lighter option: CSS content-visibility: auto skips rendering off-screen content while keeping it in the DOM.

Interview answer

For very long lists, rendering every row creates thousands of DOM nodes, which slows initial render, scrolling and memory. Virtualization renders only the rows in the viewport plus an overscan buffer, positions them inside a container sized to the full list so the scrollbar is accurate, and swaps content as the user scrolls. Libraries like TanStack Virtual or react-window handle the math. A simpler alternative is content-visibility auto with contain-intrinsic-size. The trade-offs are browser find-in-page, accessibility and variable row heights.

The analogy

A train window. You only see a few metres of track at a time; the track you can't see doesn't need to be painted in front of you, it just needs to be there when you reach it.

How it works

/* Lighter alternative: let the browser skip off-screen rendering */
.row {
  content-visibility: auto;
  contain-intrinsic-size: auto 56px;   /* estimated height so scroll size stays stable */
}

Common traps

  • Ctrl+F can't find rows that aren't rendered (with JS virtualization).
  • Screen readers may not know the full list length; set aria-rowcount / aria-setsize.
  • Unknown row heights make the scrollbar jump; measure dynamically or estimate well.

See it yourself

DevTools → ⋮ → More tools → Performance monitor → watch DOM Nodes while scrolling a virtualized list: it stays flat. On a normal list it's huge from the start.

Quick quiz

How does a virtualized list keep the scrollbar size correct?

The scroll container contains a spacer with the full list's total height, and visible rows are positioned within it.

What's overscan?

A few extra rows rendered above and below the viewport, so fast scrolling doesn't show blank space.

Name a downside of virtualization.

Browser find-in-page misses unrendered rows; accessibility needs extra work; variable heights are tricky.

  • Render only visible rows + overscan; a tall spacer keeps the scrollbar right; rows are recycled. Libraries: TanStack Virtual, react-window.
  • Lighter option: content-visibility: auto + contain-intrinsic-size (stays in DOM). See it: Performance monitor → DOM Nodes stays flat.
  • Trap: Ctrl+F misses unrendered rows, screen readers, unknown heights → jumpy scrollbar.
