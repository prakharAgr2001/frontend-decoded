The showdown

Cheat sheet: key ideas, DevTools tricks and interview traps.

  1. Audio/video/peer data → WebRTC. 2. Client sends often, low latency (chat, games, cursors) → WebSockets.
  2. Server pushes, client listens (scores, notifications, AI answers) → SSE. 4. Rare updates / delay OK → polling (long polling if faster).
  3. SSE: one-way, built-in reconnect, text, plain HTTP. WS: two-way, binary, DIY reconnect, leaves HTTP after upgrade. Polling: most compatible, most wasteful.
  4. Trap: "chat needs WebSockets" → not necessarily: SSE down + POST up is valid and stays plain HTTP (caching, auth, load balancing).
