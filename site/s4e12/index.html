Key points

  • useQuery({ queryKey, queryFn }) returns data, isPending and error. The query key is the cache address: same key = one shared request.
  • It uses stale-while-revalidate: show cached data immediately, refetch in the background, swap in new data if it changed.
  • staleTime = how long data counts as fresh (default 0). gcTime = how long unused data stays in memory (default 5 minutes).

Interview answer

React Query caches server data by query key. When a component calls useQuery, cached data is returned immediately if present, and if it's stale a background refetch runs and updates the cache. staleTime controls how long data is considered fresh, which prevents refetches, and gcTime controls how long inactive data is kept before being garbage collected. It refetches automatically on window focus, network reconnect and mount when data is stale. I use isPending for the initial loading skeleton and isFetching only for subtle background indicators.

The analogy

A newspaper on your table. staleTime: how long you trust today's paper before you want a new one. gcTime: how long an old paper sits on the table after you stop reading it before it goes in the recycling.

How it works

import { useQuery } from '@tanstack/react-query';

function Orders({ page }) {
  const { data, isPending, isFetching, error } = useQuery({
    queryKey: ['orders', page],                       // cache address
    queryFn: () => fetch(`/api/orders?page=${page}`).then(r => r.json()),
    staleTime: 30_000,                                // fresh for 30 s → no refetch on remount
  });
  if (isPending) return <OrdersSkeleton />;           // no data yet
  if (error) return <ErrorState />;
  return <OrderList orders={data} refreshing={isFetching} />;   // background refresh indicator
}

Common traps

  • isPending vs isFetching. Showing a full spinner on isFetching flashes on every background refetch.
  • staleTime 0 by default means lots of refetches; tune it per query.
  • Non-unique keys (forgetting page in the key) mix up cached data.

Quick quiz

staleTime vs gcTime?

staleTime: how long data is fresh (no automatic refetch). gcTime: how long unused cached data is kept in memory.

Two components call useQuery with the same key at the same time. How many requests?

One. Requests are deduplicated by key.

When should you show a full loading skeleton?

When isPending is true (no data yet), not on background fetches.

  • useQuery({ queryKey, queryFn }) → data, isPending, error. Key = cache address; same key = one request (dedupe).
  • Stale-while-revalidate: show cache now, refetch in background, swap if changed.
  • staleTime (fresh window, default 0) vs gcTime (unused data kept, default 5 min). Refetch on focus, reconnect, mount-when-stale.
  • Trap: isPending (no data yet → skeleton) vs isFetching (any request incl. background → don't flash a spinner).
