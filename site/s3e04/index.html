Key points

  • CLS (Cumulative Layout Shift) measures how much visible content moves unexpectedly while someone uses the page.
  • Good ≤ 0.1, poor > 0.25. It's one of Google's three Core Web Vitals, with LCP (loading) and INP (responsiveness).
  • Almost every shift has the same fix: reserve the space before the content arrives.

Interview answer

CLS measures how much visible content moves unexpectedly. Each shift scores impact fraction times distance fraction, shifts are grouped into bursts, and the worst burst is the CLS. Good is 0.1 or less. The main causes are images without dimensions, ads and embeds without reserved space, injected banners and font swaps, and the fix is always to reserve space before the content arrives.

The analogy

Someone pulls your chair away just as you sit down. The chair was fine; it just moved at the worst moment. That's a layout shift: you aim for "Cancel", an ad loads above it, everything slides down, and your thumb lands on "Buy".

How it actually works

Each time a visible element moves without the user causing it, the browser records a layout shift and gives it a score:

shift score = impact fraction × distance fraction

  • Impact fraction: how much of the viewport the moving elements touched (before + after positions combined).
  • Distance fraction: how far they moved, as a fraction of the viewport's height (or width).

Example: an article covers 50% of the screen. A banner loads above it and pushes it down by 25% of the screen height. The article now touches 75% of the viewport (old + new area), so impact = 0.75, distance = 0.25 → score 0.19. One banner, and you're already in "needs improvement".

Bursts, not totals

Shifts that happen close together are grouped into a session window (gaps under 1 second, the window capped at 5 seconds). Your page's CLS is the score of its worst window, so one bad moment decides the number, no matter how long the user stays.

The usual culprits and their fixes

1. Images and videos without dimensions. The browser doesn't know how tall they'll be until they load.

<!-- The browser computes the aspect ratio from these and reserves the box -->
<img src="hero.jpg" width="1200" height="675" alt="…">

img { max-width: 100%; height: auto; }   /* stays responsive, keeps the ratio */
.video-embed { aspect-ratio: 16 / 9; width: 100%; }

2. Ads, embeds and iframes. Reserve the slot's most likely size:

.ad-slot { min-height: 250px; }   /* don't collapse it to 0 when there's no ad */

3. Content injected above what the user is reading (cookie banners, "download our app" bars, late-loading announcements). Put them in reserved space, overlay them (position: fixed), or insert them below the fold.

4. Web fonts swapping in. A fallback font with different letter widths reflows the text when the real font arrives. Preload the key font and match the fallback's size:

<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

@font-face {
  font-family: 'Inter Fallback';
  src: local('Arial');
  size-adjust: 107%;   /* tune so Arial takes the same space as Inter */
}
body { font-family: 'Inter', 'Inter Fallback', sans-serif; }

5. Animating layout properties. Animating top, height or margin moves other elements. Animate transform instead: it moves pixels without changing layout, so it never counts as a shift.

Measure it in code

let cls = 0;
new PerformanceObserver(list => {
  for (const entry of list.getEntries()) {
    if (!entry.hadRecentInput) {   // shifts right after a tap/keypress don't count
      cls += entry.value;
      console.log('shift', entry.value.toFixed(3), entry.sources?.map(s => s.node));
    }
  }
}).observe({ type: 'layout-shift', buffered: true });

(This simple sum ignores session windows; for the real number use Google's web-vitals library: onCLS(console.log).)

See it yourself

  • DevTools → ⋮ → More tools → Rendering → tick Layout Shift Regions. Every shift flashes blue.
  • DevTools → Performance → record a page load → the Layout shifts track shows each one and which element moved.
  • Lighthouse / PageSpeed Insights → "Avoid large layout shifts" lists the guilty elements.

Real-world story

Yahoo! JAPAN News (over 22 billion page views a month) fixed late-loading images that shoved text down by reserving their space. Its layout-shift score dropped from about 0.2 to almost zero, and readers viewed about 15% more pages per session with 13% longer sessions. (Reel: The page that jumps under your thumb.)

Common mistakes

  • Testing only on a fast laptop. Shifts happen when things load late: test with Network throttling on "Slow 4G".
  • Setting height in CSS but width: 100%. The image stretches. Use width/height attributes plus height: auto, or aspect-ratio.
  • Collapsing empty ad slots. If no ad fills, keep the reserved space (or a placeholder), or the content jumps up.

Interview questions

What is CLS and what counts as a good score?

The largest burst of unexpected layout shifts during the page's life. Each shift = impact fraction × distance fraction. Good ≤ 0.1, needs improvement up to 0.25, poor above 0.25.

Does every movement count as a layout shift?

No. Shifts within 500 ms of a user input (tap, click, keypress) are expected and excluded. Movement done with CSS transform doesn't change layout, so it never counts. Content appearing at the end of the page without moving anything doesn't count either.

How do you prevent layout shift from images?

Always give width and height attributes (or CSS aspect-ratio) so the browser reserves the box before the image downloads; keep it responsive with max-width: 100%; height: auto.

A cookie banner is causing CLS. What are your options?

Make it an overlay (position: fixed), reserve its space from the first paint (render it server-side), or place it at the bottom where it doesn't push content.
