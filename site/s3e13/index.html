Lazy routes

Key points

  • In React, lazy routes use React.lazy(() => import('./Page')) wrapped in <Suspense fallback>.
  • Hide the delay by prefetching the route's chunk on hover or when the link is visible (Next.js <Link> does this in production).
  • After a deploy, old tabs may request chunks that no longer exist: handle ChunkLoadError.

Interview answer

I lazy-load routes with React.lazy and a dynamic import, wrapped in a Suspense boundary with a fallback that holds the layout. To avoid a visible delay on navigation, I prefetch chunks when a link is hovered or enters the viewport. I never lazy-load the landing route itself. In production I keep old chunk files available for a while after deploys and catch chunk load failures to reload the page, because users with an old tab open will request files from the previous build.

The analogy

A restaurant that starts cooking your dessert when you glance at the dessert menu, so it's ready the moment you order it.

How it works

const Orders = lazy(() => import('./pages/Orders'));
const prefetchOrders = () => import('./pages/Orders');

<Link to="/orders" onMouseEnter={prefetchOrders}>Orders</Link>

<Suspense fallback={<PageSkeleton />}>
  <Routes><Route path="/orders" element={<Orders />} /></Routes>
</Suspense>

Common traps

  • Lazy-loading the landing route delays the first paint for everyone.
  • Fallbacks that don't hold layout cause layout shift when the page arrives.
  • ChunkLoadError after deploys. Keep old chunks for a while, and on failure reload once.

See it yourself

In a React app with lazy routes, DevTools → Network → JS filter → navigate: a new chunk loads per route. Hover a prefetched link and watch it load before the click.

Quick quiz

Which component must wrap a lazy component?

<Suspense> with a fallback.

How do you make lazy routes feel instant?

Prefetch the chunk on hover, focus or when the link enters the viewport.

Why do users get ChunkLoadError after a deploy?

Their open tab still references the old build's chunk filenames, which were removed by the new deploy.
