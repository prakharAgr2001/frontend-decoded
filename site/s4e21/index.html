Key points

  • React compares state by reference. Mutating an object keeps the same reference, so React may not re-render. Deep nested spreads to avoid that are error-prone.
  • Immer's produce lets you write mutations on a draft; it records them and returns a new object, sharing unchanged parts (structural sharing).
  • Used inside RTK createSlice, useImmer, and Zustand's immer middleware.

Interview answer

React and Redux rely on immutability so they can detect changes with cheap reference checks. Updating deeply nested data immutably requires spreading every level, which is verbose and easy to get wrong. Immer's produce gives you a Proxy-based draft; you write normal mutations, Immer tracks them, creates copies only for the changed paths and reuses everything else, then returns a new immutable state, frozen in development. A common gotcha is an arrow function that both mutates and returns a value, which Immer rejects.

The analogy

Editing a shared document with "suggest changes" on. You type freely, the original stays untouched, and the result is a new version that reuses every paragraph you didn't change.

How it works

import { produce } from 'immer';

const next = produce(state, draft => {
  draft.user.address.city = 'Pune';
  draft.cart.items.push({ id: 9, qty: 1 });
});

next !== state;                    // true: new top-level object
next.settings === state.settings;  // true: untouched parts are shared

Common traps

  • produce(s, d => d.count = 5): the arrow both mutates and returns a value, and Immer throws. Use braces: d => { d.count = 5 }.
  • Mutating outside produce still breaks immutability.
  • Huge drafts in hot loops have overhead; plain updates are fine for simple cases.

See it yourself

Run the snippet in a Node REPL with Immer and check next.settings === state.settings: structural sharing in action.

Quick quiz

Why does mutating state break React updates?

The reference stays the same, so React's equality check sees no change and may skip re-rendering.

What is structural sharing?

The new state reuses all unchanged nested objects from the old state and copies only what changed.

Why does `d => d.count = 5` throw in Immer?

It mutates the draft and also returns a value; Immer doesn't know which result you meant.

  • Used in RTK createSlice, useImmer, Zustand immer middleware. Trap: d => d.count = 5 mutates AND returns → throws; use braces.
