Key points

  • Revision episode: interview questions on pagination.
  • Know why page 2 shows duplicates, why a timestamp cursor can miss items, when to use offset anyway, and how to build infinite scroll without scroll listeners.

Interview answer

For changing feeds I use cursor pagination with a compound cursor so inserts don't create duplicates and ties don't skip items. I keep offset pagination for stable data that needs jump-to-page, with a depth limit. Infinite scroll uses IntersectionObserver on a sentinel plus virtualization for long lists.

Quick quiz

Users see duplicates on page 2 of a feed. Why, and the fix?

Offset pagination plus new inserts at the top shifts rows. Switch to cursor pagination.

With a timestamp cursor, some items go missing. Why?

Several items share the same timestamp; created_at < cursor skips the ones equal to it. Use (created_at, id) as the cursor.

Product wants "jump to page 50". What do you use?

Offset pagination, capped at a reasonable depth (or a search-style approach), since cursors can't jump.

How do you implement infinite scroll without scroll listeners?

IntersectionObserver on a sentinel at the end of the list with a rootMargin to prefetch early, plus virtualization for very long lists.

  • Duplicates on page 2 = offset + inserts → cursor. Missing items with timestamp cursor = ties → (created_at, id).
  • Jump to page 50 → offset (cap the depth). Infinite scroll without scroll listeners → IntersectionObserver + rootMargin (+ virtualization).
