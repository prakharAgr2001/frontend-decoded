The context trap

2 min read

  • The analogy

  • See it yourself

Key points

  • useContext subscribes to the whole context value. Any change re-renders every consumer.
  • Trap 1: value={{ user, cart }} creates a new object every render, so consumers re-render even if nothing changed. Wrap it in useMemo.
  • Trap 2: one big context. Split by concern, and split state from dispatch. React.memo does not stop context re-renders.

Interview answer

Context is a delivery mechanism, not a state manager. Every component that reads a context re-renders when the provider's value changes, and since the comparison is by reference, passing a new object literal each render re-renders all consumers. I memoize the value, split contexts by concern so unrelated updates don't fan out, and separate the state and dispatch contexts. For frequently changing shared state I use a store with selectors, since React.memo can't block context updates.

The analogy

A WhatsApp group with the whole building. Every message, even "lift is working again", pings everyone. Separate groups per topic mean people only get the messages they care about.

How it works

const CartState = createContext(null);
const CartDispatch = createContext(null);

function CartProvider({ children }) {
  const [cart, dispatch] = useReducer(cartReducer, []);
  return (
    <CartDispatch.Provider value={dispatch}>        {/* dispatch never changes */}
      <CartState.Provider value={cart}>{children}</CartState.Provider>
    </CartDispatch.Provider>
  );
}
// A button that only adds items reads CartDispatch, so it doesn't re-render when the cart changes.

Common traps

  • React.memo on a consumer doesn't help: context changes bypass memo.
  • Putting fast-changing state (mouse position, form input) in context re-renders many components on every change.
  • Context isn't a global variable replacement for everything. Use it for rarely-changing, app-wide values.

See it yourself

React DevTools Profiler → record → click a re-rendered component → "Why did this render?" shows "Context changed".

Quick quiz

Why does `value={{ a, b }}` cause extra re-renders?

A new object is created on every provider render, so the reference always changes and all consumers re-render.

Can React.memo prevent a re-render caused by context?

No. Context updates re-render consumers regardless of memo.

When is a store better than context?

For frequently changing shared state where components should subscribe to only the slice they use (selectors).

  • useContext subscribes to the whole value. Any change → every consumer re-renders.
  • Trap 1: value={{ user, cart }} is a new object every render → useMemo it.
  • Trap 2: one big context → split by concern (UserCtx, ThemeCtx, CartCtx) and split state from dispatch.
  • React.memo does NOT stop context re-renders. Context = delivery, not a state manager; hot state → store with selectors.
  • See it: React Profiler → "Why did this render? Context changed".
