React Server Components (RSC)

Key points

  • React Server Components (RSC) run only on the server. They can be async, read the database directly, and their code is never sent to the browser.
  • Only their output travels to the browser. Interactive parts are marked 'use client', and only those ship JavaScript.
  • RSC is not the same as SSR: SSR makes HTML for the first load, then everything hydrates. Server components never hydrate.

Interview answer

React Server Components are components that execute only on the server. They can fetch data directly and use server-only dependencies, and only their rendered result, the RSC payload, is sent to the client, so their code adds nothing to the bundle. Components that need state, effects or event handlers are client components marked with 'use client', and server components pass them data as props. SSR and RSC are complementary: frameworks render both to HTML for the first load, but only client components hydrate.

The analogy

A restaurant where some dishes are cooked in the kitchen and served ready (server components), while a few come with a DIY grill at your table (client components). You only pay for the grills you actually use.

How it works

// ProductPage.jsx: a server component (the default in Next.js App Router)
import AddToCart from './AddToCart';
export default async function ProductPage({ id }) {
  const product = await db.product.find(id);        // direct DB access
  return (<>
    <h1>{product.title}</h1>
    <AddToCart productId={id} />                     {/* only this ships JS */}
  </>);
}

// AddToCart.jsx
'use client';
export default function AddToCart({ productId }) {
  const [added, setAdded] = useState(false);
  return <button onClick={() => setAdded(true)}>{added ? 'Added' : 'Add to cart'}</button>;
}

Common traps

  • useState or onClick in a server component throws an error. Move the interactive bit into a client component.
  • Props crossing the boundary must be serialisable. No functions or class instances from server to client.
  • Importing a client component makes it a client boundary, including everything it imports.

See it yourself

Open nextjs.org → DevTools → Network → click between docs pages: requests with ?_rsc= carry the RSC payload instead of a full HTML page.

Quick quiz

Does a server component's code end up in the browser bundle?

No. Only its rendered output is sent.

How is RSC different from SSR?

SSR renders components to HTML for the initial load and then hydrates all of them. Server components run only on the server, never hydrate, and can be re-fetched on navigation.

How do you add a click handler to part of a server-rendered page?

Put that part in a client component marked 'use client' and pass it data as props.

  • Run only on the server; can be async and read the DB; their code never ships. Only output (RSC payload) does.
  • Interactive parts = 'use client' components; only those ship JS.
  • See it: nextjs.org → Network → ?_rsc= requests on navigation.
  • RSC ≠ SSR: SSR = HTML for first load, then everything hydrates. RSC never hydrates, refetchable on navigation. Frameworks use both.
  • Trap: no useState/onClick in server components → pass data as props to a client component.
