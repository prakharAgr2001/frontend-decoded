Hydration mismatch

Key points

  • Hydration has one rule: the server's HTML must match the browser's first render.
  • Mismatches come from values that differ between server and browser: Date, Math.random(), window/localStorage, timezone or locale, invalid HTML nesting, browser extensions.
  • Fix: render the same placeholder on both sides, then fill browser-only values in useEffect.

Interview answer

A hydration mismatch happens when the HTML generated on the server differs from what the client renders on its first pass. Common causes are time and random values, reading browser-only APIs like window or localStorage during render, locale and timezone formatting, and invalid nesting that the browser repairs. React warns and may re-render that subtree on the client. The fix is to make the initial render deterministic, then update browser-specific values in an effect after hydration.

The analogy

Two people assembling the same flat-pack with different manuals. When they compare, the pieces don't line up, and one of them has to take it apart and redo it.

How it works

function LocalTime() {
  const [time, setTime] = useState(null);           // same on server and client
  useEffect(() => setTime(new Date().toLocaleTimeString()), []);
  return <span>{time ?? '--:--'}</span>;
}

Common traps

  • typeof window checks in render cause mismatches: the server renders one thing, the browser another.
  • suppressHydrationWarning is only for tiny, expected differences (like a timestamp), not a general fix.
  • Browser extensions that inject DOM can trigger warnings you can't reproduce in incognito.

See it yourself

In a Next.js or Remix app, render new Date().toISOString() directly in a component and reload: the console shows a hydration error pointing at the text.

Quick quiz

Why does `Math.random()` in render cause a mismatch?

The server and browser each generate a different number, so the first client render doesn't match the server HTML.

How do you safely show something that depends on localStorage?

Render a neutral placeholder first, then read localStorage in useEffect and update state after hydration.

Can invalid HTML cause hydration errors?

Yes. The browser repairs invalid nesting (like a div inside a p) when parsing, so the DOM no longer matches what React expects.

  • Rule: server HTML must equal the browser's first render.
  • Causes: Date, Math.random(), window/localStorage in render, timezone/locale, invalid nesting (<div> in <p>), extensions.
  • Fix: same placeholder on both sides → fill browser-only values in useEffect. Tiny diffs: suppressHydrationWarning.
  • Trap: typeof window checks in render CAUSE mismatches.
