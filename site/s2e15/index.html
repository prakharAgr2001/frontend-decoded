Key points

  • A Server Action is a function marked 'use server' that you call from the client like a normal function. React turns that call into a POST request to your server.
  • It works with <form action={fn}>, even before JavaScript loads (progressive enhancement).
  • It's a public endpoint: always check auth and validate the input inside it.

Interview answer

Server Actions let you define server-side functions with 'use server' and call them directly from components or pass them to a form's action. Under the hood the framework creates an endpoint and sends a POST with an action ID and the serialized arguments, then returns the result and can revalidate cached data. Forms using actions work without client JavaScript. Because anyone can call that endpoint, the action must authenticate the user and validate every input, exactly like an API route.

The analogy

A hotel room phone with a "room service" button. You just press it; you don't need to know the kitchen's number or how the order travels. But the kitchen must still check that the order really comes from a guest.

How it works

// actions.js
'use server';
export async function createTodo(formData) {
  const user = await getUser();                 // auth check
  if (!user) throw new Error('Not signed in');
  const title = String(formData.get('title') ?? '').trim();
  if (!title || title.length > 200) return { error: 'Invalid title' };   // validate
  await db.todo.create({ title, userId: user.id });
  revalidatePath('/todos');
}

// TodoForm.jsx
import { createTodo } from './actions';
export default function TodoForm() {
  return <form action={createTodo}><input name="title" /><button>Add</button></form>;
}

Common traps

  • Trusting the caller. The action is reachable by anyone who sends the right POST. Check permissions every time.
  • Returning secrets. Whatever you return is sent to the browser.
  • Using actions for data fetching. They're for mutations; fetch data in server components.

See it yourself

In a Next.js app, submit a form that uses an action → DevTools → Network: a POST to the same page with a Next-Action header.

Quick quiz

What does calling a server action do at the network level?

The framework sends a POST request to the server with an action ID and serialized arguments, runs the function, and returns the result.

Why do forms with server actions work before JS loads?

The form posts natively using standard HTML form submission; JavaScript only enhances it.

What must every server action do?

Authenticate/authorize the user and validate inputs, because it's a public endpoint.

  • 'use server' function called like a normal function → React sends a POST (Next-Action: <id> header).
  • Works with <form action={fn}> even before JS loads (progressive enhancement).
  • Trap: it's a PUBLIC POST endpoint. Always check auth and validate inputs inside the action.
