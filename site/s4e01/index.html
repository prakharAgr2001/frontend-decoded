What is state

Key points

  • State = data your UI remembers right now that can change while the page is open. If it changes and the screen must show it, it's state.
  • React's core idea: UI = f(state). You don't edit the screen; you change state with setX, and React re-renders and updates only what differs.
  • Don't store what you can compute. Derive totals, counts and filtered lists during render.

Interview answer

State is data that changes over time and affects what's rendered, like an input's value, whether a modal is open, or the items in a cart. In React the UI is a function of state: I update state through its setter, React re-runs the component, and it applies only the necessary DOM changes. I keep state minimal and derive everything that can be computed from it, because duplicated state gets out of sync.

The analogy

A scoreboard at a cricket match. The state is the runs, wickets and overs. Nobody repaints the board by hand; you update the numbers, and the board shows them. The run rate isn't stored separately, it's calculated from runs and overs.

How it works

function Cart({ items }) {
  const [coupon, setCoupon] = useState('');                  // state: changes, shown on screen
  const total = items.reduce((sum, i) => sum + i.price, 0);  // derived: computed, not stored
  return <p>Total: ₹{total} {coupon && `(code ${coupon})`}</p>;
}

Common traps

  • Storing derived values in state (useState(total)) creates two sources of truth that drift apart.
  • Mutating state directly (items.push(x)) keeps the same reference, so React may not re-render.
  • Using state for values that don't affect the UI (timer IDs, previous values). Use useRef instead.

See it yourself

React DevTools → Components → select a component → the hooks panel shows its live state; edit a value there and the UI updates.

Quick quiz

What makes something "state"?

It changes over time while the page is open and the UI must reflect it.

Why not keep `total` in useState next to `items`?

It duplicates information. If items change and you forget to update total, the UI shows wrong data. Compute it during render.

Where should a value go that changes but doesn't affect rendering?

In a ref (useRef), which persists across renders without triggering re-renders.

  • Trap: don't store what you can compute. const total = items.reduce(...), not useState(total) → two sources of truth drift.
