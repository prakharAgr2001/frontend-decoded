Race conditions

Key points

  • Responses arrive in network order, not request order. A slow old response can arrive after a newer one and overwrite it.
  • Classic case: searching "re" then "react". The "re" results arrive last and replace the "react" results.
  • Fix in React: ignore stale responses with a cleanup flag, or cancel them with AbortController.

Interview answer

A race condition in data fetching happens when multiple requests are in flight and an older one resolves after a newer one, overwriting fresh data with stale results. In a React effect I guard against it with a flag set in the cleanup function, so only the latest effect's response updates state, or I abort the previous request. Debouncing reduces the number of requests but doesn't solve the race. Libraries like React Query avoid it by keying data by query, so each response is stored under its own key.

The analogy

Two couriers. You order a red shirt, change your mind and order blue. The red one gets stuck in traffic and arrives last, so now red is the shirt in your hands.

How it works

useEffect(() => {
  let ignore = false;
  fetch(`/api/search?q=${encodeURIComponent(query)}`)
    .then(r => r.json())
    .then(data => { if (!ignore) setResults(data); });   // only the latest effect wins
  return () => { ignore = true; };                       // runs when query changes
}, [query]);

Common traps

  • "Debounce fixes it." It reduces requests, but two can still overlap.
  • Updating state after unmount from a slow response: the same cleanup flag prevents it.
  • Tabs or filters switching quickly have the same race, not just search boxes.

See it yourself

Throttle the network to Slow 3G, type quickly in a search box without race handling, and watch the results flicker to an older query.

Quick quiz

Why can an older response overwrite a newer one?

Responses complete in network order; a slower earlier request can finish last.

How does the `ignore` flag fix it?

The cleanup of the previous effect sets its flag to true when the query changes, so its late response is ignored.

Does debounce prevent race conditions?

No. It reduces how many requests are sent, but overlapping requests can still resolve out of order.
