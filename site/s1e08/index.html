DOM & CSSOM

TL;DR

  • The browser turns HTML into the DOM (a tree of objects) and CSS into the CSSOM (a tree of style rules).
  • CSS blocks rendering: nothing is painted until the CSS is loaded, otherwise you'd see a flash of unstyled page.
  • A normal <script> blocks parsing: the parser stops, downloads and runs it, then continues. defer and async fix that.

Say it in the interview

The browser parses HTML bytes into tokens and builds the DOM tree, and parses CSS into the CSSOM. CSS is render-blocking because the browser won't paint until it knows the styles. Classic synchronous scripts are parser-blocking because they might modify the DOM, so the parser pauses until they download and execute. Using defer or async, and putting critical CSS early, keeps the critical rendering path short.

The analogy

Building furniture from a manual. The HTML is the parts list: what pieces exist and how they fit (the DOM). The CSS is the paint and finish instructions (the CSSOM). You won't show the furniture to anyone until you know what colour it is. And if a step says "stop and read this other booklet first" (a script), you stop building until you've read it.

How it works

<!-- Blocks parsing until downloaded AND run -->
<script src="app.js"></script>

<!-- Downloads in parallel, runs after parsing, in order: best default -->
<script src="app.js" defer></script>

<!-- Downloads in parallel, runs as soon as it arrives (order not guaranteed): good for analytics -->
<script src="analytics.js" async></script>
  • The parser streams: it builds the DOM as bytes arrive, it doesn't wait for the whole file.
  • A preload scanner looks ahead for <link>, <script> and <img> to start downloads early, even while parsing is blocked.

Traps interviewers love

  • ⚠️ "The DOM is the HTML." No. The browser fixes broken markup (adds missing <tbody>, closes tags), and JavaScript changes the DOM afterwards. View Source shows what arrived; the Elements panel shows the live DOM.
  • ⚠️ async vs defer. defer keeps order and waits for parsing to finish; async runs whenever it's ready, in any order.
  • ⚠️ Scripts in <head> without defer delay the whole page from showing up.

See it yourself

Compare View Page Source (raw HTML) with DevTools → Elements (live DOM) on any React site. The source is nearly empty; the DOM is full.

Quick quiz

Why is CSS render-blocking?

Painting without styles would show unstyled content and then reflow everything when CSS arrives (FOUC). So the browser waits for the CSSOM before the first paint.

When would you use async instead of defer?

For independent scripts that don't depend on the DOM or other scripts, such as analytics or ads, where order doesn't matter and you want them to run as early as possible.

Why doesn't the DOM always match the HTML source?

The parser repairs invalid markup, and JavaScript adds, removes and changes nodes after load.

  • HTML → DOM tree; CSS → CSSOM tree. CSS blocks rendering; classic <script> blocks parsing.
  • View Source = what arrived; Elements = live DOM.
  • Trap: DOM ≠ HTML (browser fixes markup, JS mutates it).
