Key points

  • Observers let the browser tell you when something happens, instead of you checking over and over.
  • IntersectionObserver: "this element entered or left the screen" (lazy loading, infinite scroll, autoplay, ad impressions).
  • ResizeObserver (an element's size changed), MutationObserver (the DOM changed), PerformanceObserver (performance entries like long tasks and layout shifts).

Interview answer

Instead of polling or listening to scroll and resize and measuring elements myself, which forces layout on the main thread, I use observers. IntersectionObserver reports when an element crosses a visibility threshold relative to the viewport or a root, which is ideal for lazy loading and infinite scroll. ResizeObserver reports element size changes, MutationObserver reports DOM changes, and PerformanceObserver streams performance entries. They're efficient because the browser computes the information during its own rendering work and only calls you when something actually changes.

The analogy

Instead of asking "are we there yet?" every 5 seconds (a scroll listener running getBoundingClientRect()), you ask the driver to tap you when we reach the exit. The driver already knows where the car is; you only get interrupted when it matters.

How it works

// Lazy-load images when they come within 200px of the screen
const io = new IntersectionObserver(entries => {
  for (const entry of entries) {
    if (!entry.isIntersecting) continue;
    const img = entry.target;
    img.src = img.dataset.src;
    io.unobserve(img);              // done with this one
  }
}, { rootMargin: '200px' });

document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));

// Infinite scroll: load more when the sentinel at the bottom appears
new IntersectionObserver(([e]) => e.isIntersecting && loadMore())
  .observe(document.querySelector('#sentinel'));

Common traps

  • Forgetting to disconnect. Call unobserve() or disconnect() when done, or on unmount, to avoid leaks.
  • Native lazy loading exists. For simple images, <img loading="lazy"> is enough. Use IntersectionObserver for custom behaviour.
  • MutationObserver callbacks are batched microtasks, not synchronous per change.

See it yourself

Open a long page with many images, paste the lazy-load snippet into the Console (after changing a few src to data-src), and watch the Network tab: images load only as you scroll near them.

Quick quiz

Why is IntersectionObserver better than a scroll listener for lazy loading?

It fires only when visibility crosses a threshold, and the browser computes intersections itself, so your code doesn't run on every scroll or force layout with getBoundingClientRect.

What does rootMargin do?

It grows or shrinks the root's box, e.g. '200px' triggers the callback 200 px before the element actually enters the viewport, so content is ready in time.

Which observer would you use to react to an element's width changing (not the window's)?

ResizeObserver.

  • IntersectionObserver (lazy load, infinite scroll, autoplay, impressions), ResizeObserver, MutationObserver, PerformanceObserver.
  • Better than scroll listeners: browser computes intersections, no forced layout in your code, fires only on threshold crossings.
