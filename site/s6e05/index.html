Key points

  • A WebSocket starts as an HTTP GET with Upgrade: websocket. The server replies 101 Switching Protocols, and the same connection then carries frames both ways.
  • Frames have tiny headers (2–14 bytes) vs hundreds of bytes for HTTP headers. wss:// runs over TLS.
  • WebSockets do not reconnect by themselves. Reconnecting, catching up and resending are your job.

Interview answer

A WebSocket connection begins with an HTTP upgrade handshake and then switches to a persistent, full-duplex protocol over the same TCP connection, where both sides can send text or binary frames with very little overhead. It's the right choice when the client also sends frequently with low latency, like chat, games or collaborative cursors. The browser API is simple, onopen, send, onmessage and onclose, but the application must handle reconnection, heartbeats, ordering and message acknowledgements. Each message is a separate task on the main thread, so I batch bursts and render once per animation frame.

The analogy

A phone call versus sending letters. After dialling (the HTTP upgrade), both people can talk any time without re-addressing an envelope for every sentence.

How it works

const ws = new WebSocket('wss://chat.example.com/socket');
ws.onopen = () => ws.send(JSON.stringify({ type: 'join', room: 'general' }));

let queue = [];
ws.onmessage = e => {
  queue.push(JSON.parse(e.data));
  if (queue.length === 1) requestAnimationFrame(() => { renderMessages(queue); queue = []; });  // batch bursts
};
ws.onclose = e => scheduleReconnect(e.code);      // not automatic: you must reconnect (E10)

Common traps

  • No automatic reconnect. A dropped connection stays dropped until your code reconnects.
  • Rendering on every message in a burst floods the main thread. Batch per frame.
  • Load balancers must support the Upgrade header and long idle timeouts.

See it yourself

WhatsApp Web → DevTools → Network → WS → click the socket → Headers shows the 101 Switching Protocols upgrade; Messages shows the frames.

Quick quiz

What status code completes the WebSocket handshake?

101 Switching Protocols.

Does a WebSocket reconnect automatically after a drop?

No. The application must implement reconnection (unlike EventSource).

Why are WebSockets more efficient than polling for chat?

One persistent connection with tiny frame headers instead of repeated HTTP requests with full headers, and the server can push instantly.

  • Starts as HTTP GET with Upgrade: websocket → 101 Switching Protocols → same TCP connection carries frames both ways.
  • Frame header 2–14 bytes vs hundreds of bytes of HTTP headers. wss:// = over TLS.
  • API: onopen, send, onmessage, onclose. Each message is a task (S1E15) → batch bursts, render once per frame (requestAnimationFrame).
  • Trap: WebSockets do not reconnect by themselves. Reconnect, catch up and resend are your job (E10).
