LCP image priority

Key points

  • Images start at Low priority and are only boosted after layout shows they're in the viewport. That's too late for the hero.
  • Add fetchpriority="high" to the LCP image. Google's test on Google Flights improved LCP from 2.6 s to 1.9 s.
  • The image must be discoverable early: a plain <img> in the HTML, or a <link rel="preload">. Never lazy, never waiting on client JS.

Interview answer

Browsers fetch images at low priority until layout confirms they're visible, so the LCP hero often starts downloading late. I put the hero as a real img tag in the server HTML so the preload scanner finds it immediately, add fetchpriority high, and never lazy-load it. If the image is referenced only from CSS or created by JavaScript, I add a preload link with fetchpriority high. I use high priority only for one or two critical images, since marking everything high defeats the purpose.

The analogy

Airport boarding. Normally everyone boards by row, but you can hand the hero image a priority pass so it skips the queue. Give priority passes to everyone and it's just a queue again.

How it works

<img src="/hero-1200.avif" width="1200" height="600" fetchpriority="high" alt="Sale banner">

<!-- Hero only referenced in CSS? Preload it -->
<link rel="preload" as="image" href="/hero-1200.avif" fetchpriority="high">

Common traps

  • fetchpriority="high" on many images = nothing is high anymore.
  • Carousels where the first slide is set by JS: the browser can't find it early.
  • Lazy-loading everything by default, including above-the-fold images.

See it yourself

DevTools → Network → enable the Priority column → reload. The hero should show High and start near the top of the waterfall.

Quick quiz

What priority do images normally start with?

Low, boosted to high only once layout shows they're in the viewport.

Why can't the preload scanner find a CSS background hero?

The URL is inside a stylesheet that must be downloaded and parsed first, then matched to elements.

How many images should get fetchpriority="high"?

Usually just the LCP image (one, maybe two).

  • Images start Low and are boosted only after layout. fetchpriority="high" on the hero (Chrome team test on Google Flights: LCP 2.6 s → 1.9 s).
  • Must be discoverable by the preload scanner: plain <img> in HTML, or <link rel="preload" as="image" fetchpriority="high">. Never lazy, don't wait for client JS.
  • Trap: high priority on everything = nothing is high priority.
