Key points

  • In REST, everything is a resource with its own URL (/users/42, /posts/7/comments), and you act on it with HTTP verbs.
  • GET read · POST create · PUT replace the whole thing · PATCH change some fields · DELETE remove. Common status codes: 200 OK, 201 Created, 404 Not Found.
  • fetch does not throw on 404 or 500. Always check res.ok.

Interview answer

REST models data as resources identified by URLs and uses HTTP methods for operations: GET to read, POST to create, PUT to replace, PATCH to partially update and DELETE to remove, with status codes describing the result. GET, PUT and DELETE are idempotent, meaning repeating them has the same effect, while POST is not, which matters when retrying. Because it uses plain HTTP, REST works naturally with caching, CDNs and browser tooling. On the client, fetch only rejects on network failures, so I check response.ok for HTTP errors.

The analogy

A library. Every book has its own shelf address (URL). You can read a book (GET), add a new one (POST), swap an entire book for a new edition (PUT), correct a page (PATCH), or remove it (DELETE).

How it works

async function getUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);   // fetch doesn't throw on 404/500
  return res.json();
}

await fetch('/api/orders', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ itemId: 7, qty: 1 }),
});

Common traps

  • Not checking res.ok. A 500 error page gets parsed as if it were data.
  • PUT vs POST is about idempotency. Five identical PUTs leave one user; five POSTs may create five orders.
  • Verbs in URLs (/getUser, /createOrder) aren't RESTful; the verb is the HTTP method.

See it yourself

Open https://api.github.com/users/torvalds in a browser tab: a REST resource as JSON. DevTools → Network shows the GET and its 200 status.

Quick quiz

Which methods are idempotent?

GET, PUT, DELETE (also HEAD, OPTIONS). POST isn't; PATCH isn't guaranteed.

Does fetch throw on a 404?

No. It resolves with res.ok false; it only rejects on network errors.

PUT vs PATCH?

PUT replaces the whole resource; PATCH changes only the fields you send.
