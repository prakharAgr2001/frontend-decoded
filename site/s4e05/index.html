Key points

  • Revision episode: interview questions on state basics.
  • Know props vs state, the five kinds of state and their homes, why typing in a search box can re-render a whole page, and how to stop context fan-out.

Interview answer

Props are inputs passed from a parent and read-only; state is owned by a component and changes over time. I keep state minimal and local, derive what I can, choose the right home for server, URL and form state, and fix unnecessary re-renders by moving state down before reaching for memoization.

Quick quiz

Props vs state?

Props are passed in by the parent and are read-only for the child. State is owned by the component and changes via its setter. Values that can be computed should be derived, and values that don't affect rendering belong in refs.

Name the five kinds of state and their homes.

Local UI → useState. Shared client → context/store. Server → query cache. URL → search params/path. Form → form library.

Typing in a search box re-renders the whole page. Why, and how do you fix it?

The search state lives too high (e.g. in the page or App), so every keystroke re-renders everything below it. Move the state down into the search component, or pass heavy sections as children.

Every context consumer re-renders on any change. Fixes?

Memoize the provider value, split contexts by concern, separate state and dispatch contexts, or move hot state to a store with selectors. React.memo won't help.
