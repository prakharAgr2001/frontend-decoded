Layout → Paint → Composite

TL;DR

  • After DOM + CSSOM, the browser runs a pipeline: render tree → layout → paint → composite.
  • Layout works out where and how big every box is. Paint fills in pixels (text, colours, shadows). Composite stacks painted layers on the GPU.
  • display: none removes an element from the render tree; visibility: hidden keeps its space.

Say it in the interview

The browser combines the DOM and CSSOM into a render tree of visible elements with their computed styles. Layout calculates the exact size and position of each box. Paint records drawing commands and rasterises them into layers, and compositing combines those layers on the GPU into the final frame. Changes later in the pipeline are cheaper: a transform only needs compositing, while a width change triggers layout, paint and composite again.

The analogy

Making a magazine page. Render tree: decide which articles make it in. Layout: draw the grid and box sizes on the page. Paint: print the text, photos and colours into each box. Composite: stack transparent sheets (layers) on top of each other to get the final page.

How it works

  • Layout depends on the parent: a box's width usually comes from its container, its height from its children, so changes ripple.
  • Some elements get their own layer (videos, transform/opacity animations, will-change), so they can move without repainting the rest.

Traps interviewers love

  • ⚠️ display: none vs visibility: hidden vs opacity: 0. None: not in the render tree, no space. Hidden: takes space, not visible, not clickable. Opacity 0: takes space, invisible, still clickable.
  • ⚠️ "Paint means drawing to the screen." The screen update is the composite step; paint produces layer bitmaps.
  • ⚠️ Too many layers. Each one costs GPU memory; promoting everything makes things slower, not faster.

See it yourself

DevTools → Performance → record a page load. Purple blocks are Layout (and style), green blocks are Paint. DevTools → ⋮ → More tools → Layers shows each composited layer.

Quick quiz

What's in the render tree, and what isn't?

Visible nodes with computed styles. Not included: <head>, <script>, display: none elements and their children. visibility: hidden elements are included (they take space).

Order the stages: paint, layout, composite, style.

Style → Layout → Paint → Composite.

Why is animating transform cheaper than animating left?

left changes geometry, so every frame needs layout + paint + composite. transform is applied at composite time on an existing layer, so it skips layout and paint.

  • Render tree (visible nodes) → Layout (size/position) → Paint (pixels) → Composite (GPU stacks layers).
  • Performance panel: purple = layout, green = paint.
  • Q: display:none removes from render tree (no space); visibility:hidden keeps the space.
