Smooth animation

TL;DR

  • Smooth = 60 frames a second, about 16.7 ms per frame, including your JS, style, layout and paint.
  • Animate transform and opacity. They run on the compositor (GPU) and skip layout and paint.
  • will-change: transform promotes an element to its own layer ahead of time. Use it sparingly: every layer costs GPU memory.

Say it in the interview

For smooth 60 fps animation each frame has about 16 ms, so I avoid animating properties that cause layout or paint, like width, top or box-shadow. I animate transform and opacity, which can be handled by the compositor thread on the GPU, often even when the main thread is busy. I use CSS transitions or the Web Animations API, or requestAnimationFrame for JS-driven motion, and will-change only on elements that are about to animate.

The analogy

A flipbook. Each page must be drawn in time or the motion stutters. Animating left is like redrawing the whole page for every flip. Animating transform is like sliding a cut-out sticker across the same page: much faster.

How it works

.card { transition: transform 200ms ease, opacity 200ms ease; }
.card:hover { transform: translateY(-4px) scale(1.02); }

/* Only for elements about to animate, remove when done */
.drawer.opening { will-change: transform; }
  • CSS transitions and animations on transform/opacity can keep running smoothly even if JavaScript blocks the main thread for a moment.
  • For JS-driven motion, use requestAnimationFrame and base movement on time, not on frame count.

Traps interviewers love

  • ⚠️ will-change on everything. Creates many layers, eats GPU memory, and can make things slower, especially on phones.
  • ⚠️ "translateZ(0) hack." It forces a layer like will-change, with the same costs. Know why it works before using it.
  • ⚠️ 120 Hz screens. The budget is about 8.3 ms per frame, so heavy JS hurts even more on modern phones.

See it yourself

DevTools → Rendering → tick Frame Rendering Stats (live FPS meter) and Layer borders. Compare animating left vs transform on the same element.

Quick quiz

Why is transform animation smoother than top/left?

It doesn't change layout, so the browser can skip layout and paint and just move an existing layer on the compositor, often on the GPU.

What does will-change do, and what's the risk?

It hints the browser to create a compositor layer in advance. Overusing it creates too many layers and wastes memory.

How many milliseconds per frame at 60 fps?

About 16.7 ms (1000 / 60), and the browser needs part of that for its own work, so aim for about 10 ms of your code.

  • Animate transform/opacity (compositor, GPU layer) not left/top/width (layout every frame).
  • will-change: transform hints a layer — each layer costs GPU memory, don't overuse.
  • Check: Rendering → Frame Rendering Stats.
